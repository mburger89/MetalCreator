# DIM-3 Model Dimensions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Feature dimensions on the part: nodes declare `DimensionSpec`s at evaluation, the selected feature (node or clicked face)
shows its own and its private chain's, any can be pinned (saved), and a typed value commits, evaluates and is taken back
invisibly when it makes the edited node or anything downstream fail.

**Architecture:** `CreatorGraph` gains the data (`DimensionSpec`, `DimensionTarget`, `DimensionPin`, pins on every `Graph`), the
evaluator's collection of specs into `NodeResult`, a result **hold** on `DocumentModel` with a withdrawable last step, and a
level-producer table that turns a face's `TopoTag` nodes into nodes of the level shown. `CreatorNodes` declares specs. `CreatorApp`
walks the private chain, builds `OverlayDimension`s (`FeatureDimensionBuilder`, beside `HandleBuilder`), answers `"feature/…"`
IDs through DIM-1's `DimensionEditing` router, and runs every value-box commit through `AppModel.commitChecked`. `CreatorViewport`
gains only a hover note and a declutter pass; it still never learns about the graph.

**Tech Stack:** Swift 6.4, MetalUI (`../MetalUI`, read only), Swift Testing, `FakeKernel` (OpenCascade only in gated tests).

**Spec:** `docs/superpowers/specs/2026-10-27-driving-dimensions-design.md` §3.1–§3.4, §7 (refusal and rollback), §8 (pins), §10.

## Decisions taken here (touch the spec, saved data or what the user sees)

1. **Coverage (§3.2).** The app has no B-rep Box, Cylinder, Sphere or Shell node; the implicit Box, Cylinder, Sphere and Shell are
   covered. Rectangle (width, height) and Circle (Ø) are added, so a plain extruded plate shows its sizes. A cylinder's and a sphere's
   radius input shows as Ø (`inputScale` 0.5). A full 360° Revolve and a 360° Circular sweep show no angle. Per-instance reference
   dimensions are capped at the first 24 instances.
2. **The private chain never crosses a body wire** (a link of type `.solid`, `.implicit` or `.mesh`): without this, clicking the
   hole pattern on a plate would show the plate's sketch and depth too, against §1's scenario. A node flagged `isOutput` counts as
   having another consumer. The walk stops at Graph Parameter and Group Input nodes.
3. **Face click selects only in Final preview** (in Selected-node preview the selection chooses what is shown, so a click would
   switch the preview). A click on empty space clears the graph selection; a click on a face with no tags (implicit meshes) changes
   nothing. Rule for a face: its tags' nodes, resolved to the level shown; the most downstream of them; if it declares no dimensions,
   the nearest upstream node that does (breadth-first over its inputs, lowest ID first). An edge uses the union of its faces' tags.
4. **Rollback.** `DocumentModel` holds its published results (`results`, `innerResults`, `lastGoodOutputs`, no `.evaluating` marks)
   from before the commit until the check ends, so neither the viewport, the graph panel's badges nor the inspector shows the
   candidate. A refusal restores the content and the undo history as they were (the redo list included). An edit superseded during
   the check (Undo from the menu, another edit) is left alone and the box closes as accepted. Only **new** errors refuse: a node
   already failing with the same message before the edit does not.
5. **Undo names:** a feature input is "Change Dimension"; a parameter edit stays "Change Parameter" (the spec's "Change <parameter
   label>" would put typed text in an undo name, which the overview forbids).
6. An exposed sketch dimension wired from a graph parameter is editable through the parameter (the user's parameter rule wins over the
   spec's "an exposed sketch dimension that is wired: reference").
7. **Pins** live on each graph (top level and each group definition) and show only at the level the panel shows. Removing a node
   removes its pins (undo restores them); a pin whose input or sketch dimension has gone stays in the file and shows nothing (it
   comes back with an undo that restores the dimension). Opening a file keeps pins naming a node that isn't there (sorted, unique) and the builder shows nothing for them (spec Errata; ruling at the DIM-3 final review).
8. Feature-mode edits of a sketch dimension have no flip refusal until DIM-2's `SketchFlipCheck` merges (see Overlap).

## Review Focus

2. The user acts during "Checking…" (⌘Z, an inspector edit, deleting the node). Expected: no withdrawal over their action, box closes, history intact. Tests: Task 4 `aSupersededStepIsNotWithdrawn`, Task 13 `deletingTheNodeWhileCheckingClosesTheBox`.

### Task 4: Holding results and withdrawing a step (the riskiest piece)

**Files:**
- Create: `Sources/CreatorGraph/TentativeStep.swift`
- Modify: `Sources/CreatorGraph/DocumentModel.swift` (the members below; `perform` records the step; `undo`/`redo` clear it; `didChange` and `apply(_:)` respect the hold)
- Test: `Tests/CreatorGraphTests/Dimensions/DocumentHoldTests.swift`; `Tests/CreatorGraphTests/Support/DimensionTestNodes.swift` (+`ThresholdNode`: errors "Too big." when `value` > 50; +`GatedNode` with a `Gate` actor whose `open()` releases every waiting evaluation)

**Interfaces (Produces):**

```swift
public struct TentativeStep: Sendable {
    public let watched: Set<NodeID>               // top-level touched nodes and their downstream closure (the stale set)
    let contentBefore: GraphContent, contentAfter: GraphContent
    let historyBefore: UndoStack
    let errorsBefore: [NodeID: String]           // top-level .error messages before the step
}
public struct StepProblem: Sendable, Equatable { public var node: NodeID; public var message: String }
extension DocumentModel {
    public private(set) var isHoldingResults: Bool                   // stored
    public func holdResults()
    public func releaseResults()                                     // publishes a held report, if any
    public func lastStep() -> TentativeStep?                         // the last `perform`'s, nil after undo/redo
    public func newProblem(in step: TentativeStep) -> StepProblem?   // reads the held report if holding, else `results`
    @discardableResult public func withdraw(_ step: TentativeStep) -> Bool
}
```

- `perform` (not coalesced only) stores a `TentativeStep` before applying: the stale set already computed, `content`, `undoStack`, the
  `.error` messages of `results`. While holding: `didChange` neither filters nor marks `.evaluating` (it still schedules), and
  `apply(report)` stores the report as `heldReport` instead of publishing; `releaseResults` sets the flag off and applies `heldReport`.
- `newProblem`: among `watched` nodes whose held (or current) state is `.error(m)` with `errorsBefore[id] != m`, the first in
  `graph.evaluationOrder(for: watched)` order; the message is the first line of `m`. `nil` while the report for the step's content has
  not arrived (callers await `waitForEvaluation()` first).
- `withdraw`: only when `content == step.contentAfter` and `undoStack.undoEntries.count == step.historyBefore.undoEntries.count + 1`;
  then `content = step.contentBefore`, `undoStack = step.historyBefore`, `heldReport = nil`, the step forgotten, evaluation scheduled
  (all cache hits); returns false otherwise and changes nothing.
