# Adopt MetalUI C21 (the glass blur) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the flat `glass` tint of every floating panel with a real backdrop blur: a MetalUI material that blurs what is drawn beneath it (the viewport included), with the theme's `glass` role laid over it, so gap C10-a is closed; honour Reduce Transparency ourselves (MetalUI does not); say honestly what C21 leaves.

**Architecture:** A pure model in `CreatorStyle` decides everything: `GlassSurface` (which floating surface) gives a `GlassThickness` (a MetalUI material), `GlassStyle` is that material plus the theme's `glassFill` at an opacity lowered so the pair hides what the role's opacity says (`(1 - tint) * (1 - material) = 1 - glass`), and `glassBackground(_:in:)` draws it (tint first, material behind it). `GlassPanel(_ surface:)` and the two sketch chips read the style; behaviour stays in the model and the views stay thin. Reduce Transparency is a `@MainActor @Observable GlassAppearance` in the environment, fed by `ReduceTransparencyFeed` (injected setting and change stream, tested) and read from AppKit by one small file in the executable. Tests assert frames: one backdrop record per panel, in the panel's box, painted after the viewport's surface, under the theme's tint; the look over a moving viewport is human check group C21.

**Tech Stack:** Swift 6.4 strict concurrency, Swift Testing, MetalUI at `../MetalUI` master `d6a815c` or later (checked at `930db4a`) (C21: `.background(.ultraThinMaterial)` and the other four thicknesses blur what MetalUI drew beneath them, `Scene.backdrops`), AppKit for one setting (`NSWorkspace`), SwiftLint.

**Spec:** `docs/superpowers/specs/2026-10-07-metalcreator-vertical-slice-design.md` §6.1 (glass panels: "blur and a 1-pt hairline border"), §6.6 (the Glass panels row of the colour table, the themes), §9 (MetalUI dependency and gaps; the risk "the cost of glass blur over a continuously redrawing `MetalView`"), its Errata (M5) (the glass bullet this plan rewrites) and all its other Errata; `docs/metalui-gaps.md` entry C10-a (and M5-c); the C10 adoption plan `docs/superpowers/plans/2026-10-09-adopt-c10.md` Task 5 (the decision this plan reverses, now that the API exists). ## Review Focus

Inputs and conditions the spec implies and a person will hit, most likely first, each pinned by a test in the task that owns the code (the last has none, and says why):

1. **A glass opacity at either end** (a custom theme with Glass at 0%, at 100%, or lower than the material's own opacity): the tint's opacity is never below 0 or above 1, 0% leaves the bare material, 100% stays opaque, a more opaque glass never gets a thinner tint, and a fully opaque material cannot divide by zero (Task 1, `aMoreOpaqueGlassNeverGetsAThinnerTint`, `aThickerMaterialLeavesLessForTheTintAndAnOpaqueGlassStaysOpaque`, `aMaterialThatIsFullyOpaqueGetsNoTintAndNothingDividesByZero`).

3. **Reduce Transparency switched on while the app runs, switched off again, and on at launch**: every panel and chip follows in both directions, opaque with no material while on (Task 4, `eachChangeReReadsTheSettingBothWays`, `aSettingTurnedBackOffClearsTheAppearance`, `theAppearanceHasTheSettingAtOnce`, `withReduceTransparencyOnAPanelIsTheThemesColourOpaqueAndBlursNothing`, `withReduceTransparencyOnNoPanelBlursAndEachIsOpaque`).
4. **Glass floating over other glass** (the palette over the graph panel and the viewport, the theme editor over the inspector, the pick banner over the viewport): every material record is painted after the viewport's surface and the palette's after the graph panel's (Task 2, `GlassBlursViewportTests`, `thePalettesGlassBlursTheViewportAndTheGraphPanelBeneathIt`).
5. **A click in a gap of the sketch toolbar or inspector** must not reach the viewport beneath, as before: the glass still only paints (a material is a background decoration like a colour, and MetalUI gives a painted view no hitbox, its divergence 141), so `SketchChrome` keeps its opaque backdrop and its comment says why. No automated test: the window harness would need a sketch session and a pointer-sensitive tool to see a click arrive; it is human check C21-4.

## User decisions (defaults used by this plan)

Product choices the spec leaves open. Each has a recommended default that this plan implements; the alternative is a small change, named here.

1. **Which material thickness per panel.** Default: `.ultraThin` for every persistent surface (graph panel, inspector, top bar, pick banner, Show graph button, theme editor, sketch chips) and `.thin` for the add-node palette. Why: with the tint sized against the material (decision D1), the thickness no longer changes how much of the backdrop shows, only how much of the visible tint is MetalUI's grey and how much is the theme's colour; the thinnest keeps Dracula's `#21222c` truest, and the palette, which floats over the graph panel's glass and a busy canvas, gets one step more grey to stand apart. Alternatives: every surface `.thin` or `.regular` (greyer, closer to macOS); per-surface tuning after human check C21-2. Change: one `switch` in `GlassSurface.thickness` and its pinning test.
2. **Reduce Transparency.** Default: honoured by the app (MetalUI does not, divergence 249): while the system setting is on, every glass surface is the theme's glass colour at full opacity with no material and no blur. Why: it is an accessibility setting the HIG asks apps to respect; the cost is one `@Observable`, one tested feed and ten lines of AppKit in the executable. Alternatives: not honoured (delete Task 4 and `GlassStyle.reducesTransparency`; the blur is on whatever the setting says), or honoured but with the fallback at the role's own opacity (today's flat look, still see-through; change `GlassStyle.tint`'s first line to `fill`). The gap C21-b is logged either way.
3. **The sketch chips (readout and inference).** Default: glass like the panels (a `.ultraThin` material under the theme's tint). Why: one look for every floating surface, and the same Reduce Transparency behaviour. Cost: two more blur passes while the pointer moves in a sketch, and a small box blurs only its own contents (divergence 247), so a chip is a soft patch of the backdrop's average, which may read as flat. Alternative: leave the chips on the flat tint (revert Task 3's two view lines, keep `SketchColors.glass`); decide after human checks C21-2 and C21-8.

## Decisions made in this plan

- **D1. How the theme's tint combines with a material.** A panel is the material, the theme's `glassFill` colour over it, and the hairline over both. The role's opacity keeps its meaning (how much of the backdrop the panel hides), so the tint's own opacity is `1 - (1 - glass) / (1 - material)`, clamped to 0...1: Dracula's 86% over `.ultraThinMaterial` (50.59% in dark) is a 71.7% tint, and the pair hides 86%. Laying the role's 86% over the material unchanged would hide 94% and leave the blur at about 6% of the pixels, nothing anyone could see; lowering the role in the theme editor still brightens the blur, as C21-1 does on purpose. The colour is always the role's, so a theme editor edit, Alucard's light glass and Nord's follow with no new role and no file-format change.
- **D2. The material is drawn in the theme's scheme**, not the window's: `shape.fill(material).environment(\.colorScheme, ...)` on the material layer only. The app sets the window's scheme from the theme already (`AppRoot.preferredColorScheme`), so this changes nothing in the app, and it makes headless frames (whose scheme is light) draw what the app draws.
- **D3. `GlassPanel` takes its surface as a required parameter**, so a new panel cannot forget to choose a thickness, and `GlassSurface` lives in `CreatorStyle` because the chips (in `CreatorSketchEditor`) cannot import `CreatorEditor`.
- **D4. `SketchChrome` keeps its opaque backdrop** and its reason (see Review Focus 5). `TopBar` and `InspectorDock` pass `.topBar` and `.inspector` to it.
- **D5. The opacity table is copied** (`GlassThickness.materialOpacity(isDark:)`) because MetalUI keeps it internal (gap C21-a); `GlassMaterialTableTests` renders every material in both schemes and compares, so a MetalUI change fails a test here.
- **D6. Nothing is benchmarked.** MetalUI does not run a `MetalView`'s draw headless (`HT-Q`), so the GPU cost of the blur cannot be measured by the tests; spec §9 names it as a risk, and human check C21-3 compares an orbit with the blur and with Reduce Transparency on.

```swift
import CreatorStyle

/// The glass model (spec §6.1, §6.6): what a surface is built on, and how the theme's tint combines with a material.
@MainActor
struct GlassStyleTests {
    @Test(arguments: GlassThickness.allCases, [true, false])
    func theMaterialAndTheTintTogetherHideAsMuchAsTheThemesGlassDid(_ thickness: GlassThickness, _ isDark: Bool) {
        let material = thickness.materialOpacity(isDark: isDark)
        let tint = GlassStyle.tintOpacity(glass: 0.86, materialOpacity: material)
        if tint > 0 {
            #expect(abs((1 - tint) * (1 - material) - 0.14) < 1e-9, "\(thickness) \(isDark): the backdrop left over")
        } else {
            #expect(material >= 0.86, "no tint is only for a material already as opaque as the glass")
        }
    }

    @Test func draculaGlassOverTheThinnestMaterialIsA72PercentTintOfItsOwnColour() {
        let style = GlassStyle(theme: .dracula, surface: .topBar)
        #expect(style.thickness == .ultraThin)
        #expect(style.tint.rgb == 0x21222c, "the colour is the theme's, whatever the material")
```

```swift
import CreatorStyle
import MetalUI
import Testing

/// `GlassThickness.materialOpacity(isDark:)` copies MetalUI's `LK-L` table, which MetalUI keeps internal. This renders
/// each material and reads the opacity MetalUI really gives its backdrop record, so a MetalUI change to the table fails here.
@MainActor
struct GlassMaterialTableTests {
    func backdropOpacity(_ thickness: GlassThickness, _ scheme: ColorScheme) throws -> Float {
        let scene = renderHeadless {
            ZStack {}.frame(width: Pixels(80), height: Pixels(40)).background(thickness.material)
                .environment(\.colorScheme, scheme)
        }
        return try #require(scene.backdrops.first).tint.a
    }

    @Test(arguments: GlassThickness.allCases)
    func ourTableIsMetalUIs(_ thickness: GlassThickness) throws {
        let dark = try backdropOpacity(thickness, .dark)
        let light = try backdropOpacity(thickness, .light)
        #expect(abs(Double(dark) - thickness.materialOpacity(isDark: true)) < 1e-4, "\(thickness) dark: \(dark)")
        #expect(abs(Double(light) - thickness.materialOpacity(isDark: false)) < 1e-4, "\(thickness) light: \(light)")
    }
}
```

```swift
import CreatorStyle
import MetalUI
import Testing

/// `glassBackground(_:in:)`: the material blurs what is beneath, the theme's tint is drawn over it, and a style that
/// reduces transparency draws the tint alone. What it looks like is human check C21-1.
@MainActor
struct GlassBackgroundTests {
    func frame(_ style: GlassStyle) -> Scene {
        renderHeadless {
            ZStack {}.frame(width: Pixels(120), height: Pixels(60))
                .glassBackground(style, in: RoundedRectangle(cornerRadius: Pixels(10)))
        }
    }

    func box(_ bounds: MUIBounds) -> [Float] {
        [bounds.origin.x, bounds.origin.y, bounds.size.width, bounds.size.height]
    }

    func tintRects(_ scene: Scene) -> [MUIRect] { scene.rects.filter { $0.background.a > 0 } }

    @Test func aBlurringStyleDrawsOneBackdropAndTheThemesTintOverItInTheSameBox() throws {
        let style = GlassStyle(theme: .dracula, surface: .topBar)
        let scene = frame(style)
        let backdrop = try #require(scene.backdrops.first)
        let tint = try #require(tintRects(scene).first)
        #expect(scene.backdrops.count == 1 && tintRects(scene).count == 1)
        #expect(box(backdrop.bounds) == box(tint.bounds), "the tint covers exactly what the material blurs")
        #expect(Array(box(backdrop.bounds)[2...]) == [240, 120], "120 x 60 pt at 2x")
        #expect(backdrop.cornerRadii.topLeft == 20 && tint.cornerRadii.topLeft == 20, "10 pt at 2x")
        let kinds = scene.drawList.map(\.kind)
        let backdropRun = try #require(kinds.firstIndex(of: .backdrop))
        let tintRun = try #require(kinds.firstIndex(of: .rect))
        #expect(backdropRun < tintRun, "the material is painted first, the tint over it: \(kinds)")
```

```swift
import MetalUI

/// What one glass surface looks like in one theme (spec §6.1, §6.6): a MetalUI material that blurs the backdrop, and the
/// theme's own `glassFill` over it. The theme owns the colour: the tint is the role's colour and the role's opacity is
/// still how much of the backdrop the panel lets through, as it was when the glass was a flat tint with nothing under
/// it. So the tint's own opacity is lowered to make up for the material under it (`tintOpacity(glass:materialOpacity:)`):
/// Dracula's 86% glass over `.ultraThinMaterial` is a 72% tint over the material, and the two together hide 86% of the
/// backdrop, as the flat tint did. A value, so the views stay thin and a test reads what they will draw.
public struct GlassStyle: Hashable, Sendable {
    public let thickness: GlassThickness
    /// The theme's `glassFill`: its colour and the opacity the person chose for the whole panel.
    public let fill: HexColor
    /// Whether the theme is a dark one; the material's grey and the controls follow it.
    public let isDark: Bool
    /// Reduce Transparency (divergence 249 in MetalUI: it does not honour the setting itself): no material, no blur, the
    /// theme's colour fully opaque.
    public let reducesTransparency: Bool

    public init(theme: ColorTheme, surface: GlassSurface, reducesTransparency: Bool = false) {
        thickness = surface.thickness
        fill = theme.colors.glassFill
        isDark = theme.isDark
        self.reducesTransparency = reducesTransparency
    }

    /// The style in the theme `themes` shows, or Dracula's without a store (headless tests, `GraphPanelPreview`).
    @MainActor
    public init(themes: ThemeStore?, surface: GlassSurface, reducesTransparency: Bool = false) {
        self.init(theme: themes?.current ?? .dracula, surface: surface, reducesTransparency: reducesTransparency)
    }

    /// Whether a material blurs what is drawn beneath the panel.
    public var blursBackdrop: Bool { !reducesTransparency }

    /// The theme's colour laid over the material: its role's colour at the opacity that, with the material beneath, hides
    /// as much of the backdrop as the role's own opacity says. Fully opaque when transparency is reduced.
    public var tint: HexColor {
        guard blursBackdrop else { return fill.opacity(1) }
        let material = thickness.materialOpacity(isDark: isDark)
        return fill.opacity(Self.tintOpacity(glass: fill.opacity, materialOpacity: material))
    }

    /// The colour scheme the material is drawn in: the theme's, not the window's.
    public var colorScheme: ColorScheme { isDark ? .dark : .light }

    /// The opacity of a tint laid over a material of opacity `materialOpacity` so that together they let through
    /// `1 - glass` of the backdrop: `(1 - tint) * (1 - material) = 1 - glass`. At least 0 (a material already more
    /// opaque than the glass gets no tint) and at most 1.
    public static func tintOpacity(glass: Double, materialOpacity: Double) -> Double {
        guard materialOpacity < 1 else { return 0 }
        return min(1, max(0, 1 - (1 - glass) / (1 - materialOpacity)))
    }
}
```

```swift
import MetalUI

extension GlassStyle {
    /// The material layer under the tint: the surface's material in the theme's scheme, or nothing when transparency is
    /// reduced. The scheme is set on the material only, so the panel's content keeps the window's.
    @MainActor @ElementBuilder
    fileprivate func materialLayer<S: Shape>(in shape: S) -> some ProposalElementGroup {
        if blursBackdrop {
            shape.fill(thickness.material).environment(\.colorScheme, colorScheme)
        }
    }
}

extension ElementGroup {
    /// Fills `shape` behind this view as `style` says: the material first, blurring what is drawn beneath, then the
    /// theme's tint over it (the later `background` is the one behind, so the tint is written first). A style that
    /// reduces transparency draws the tint alone.
    public func glassBackground<S: Shape>(_ style: GlassStyle, in shape: S) -> some ElementGroup {
        background(style.tint.color, in: shape).background { style.materialLayer(in: shape) }
    }
}

extension ProposalElementGroup {
    /// `glassBackground(_:in:)` for a view that is still a proposal view, so a chip can be offset after its glass.
    public func glassBackground<S: Shape>(_ style: GlassStyle, in shape: S) -> some ProposalElementGroup {
        background(style.tint.color, in: shape).background { style.materialLayer(in: shape) }
    }
}
```

```swift
/// blurs what is drawn beneath it (MetalUI C21, gap C10-a), with the theme's `glass` role laid over it
/// (`GlassStyle.tint`: Dracula's `#21222c` at 86%, lowered a little because the material under it already hides some of
/// the backdrop). The colour stays the theme's, so the theme editor's Glass role still sets it, and Alucard's light glass
/// is light. Which material, and what the tint is, are `GlassStyle`'s (CreatorStyle); this only draws it. The blur
/// sees what MetalUI drew beneath the panel in the same window, and nothing of the desktop (MetalUI divergence 245).
/// Public so the app shell's top bar and pick banner (M6) share the chrome.
public struct GlassPanel<Body: ElementGroup>: Component {
    let surface: GlassSurface
    let body: Body
    @Environment(ThemeStore.self) var themes: ThemeStore?

    public init(_ surface: GlassSurface, @ElementBuilder _ body: () -> Body) {
        self.surface = surface
        self.body = body()
    }

    public var content: some ElementGroup {
        let palette = Palette(themes)
        let style = GlassStyle(themes: themes, surface: surface)
        let shape = RoundedRectangle(cornerRadius: Pixels(10))
        return ZStack(alignment: .topLeading) { body }
            .padding(Edges(all: GraphPanelLayout.glassPadding.px))
            .glassBackground(style, in: shape)
            .overlay { shape.strokeBorder(palette.hairline.color, lineWidth: Pixels(1)) }
    }
}
```

```swift
import CreatorStyle

/// Keeps `GlassAppearance.reducesTransparency` equal to the system's Reduce Transparency setting (MetalUI divergence 249:
/// it does not honour the setting for materials). The setting and its changes come in from the shell, which reads AppKit
/// (`MetalCreatorApp`), so this has no platform code and a test can script both. The shell runs `follow()` in a task that
/// lives as long as the app, as it does `WindowChromeSync.follow()`.
@MainActor
public final class ReduceTransparencyFeed {
    let appearance: GlassAppearance
    let read: @MainActor () -> Bool
    let changes: AsyncStream<Void>

    /// `read` answers whether the setting is on now; `changes` yields once whenever the system's display accessibility
    /// options change (it need not say which). The appearance has the current answer at once.
    public init(appearance: GlassAppearance, read: @escaping @MainActor () -> Bool, changes: AsyncStream<Void>) {
        self.appearance = appearance
        self.read = read
        self.changes = changes
        appearance.reducesTransparency = read()
    }

    /// Re-reads the setting at each change, until `changes` ends.
    public func follow() async {
        for await _ in changes {
            appearance.reducesTransparency = read()
        }
    }
}
```

```swift
import AppKit

/// The system's Reduce Transparency setting (System Settings, Accessibility, Display), read from AppKit for
/// `ReduceTransparencyFeed`: MetalUI does not honour it for materials (its divergence 249, docs/metalui-gaps.md C21-b).
/// The only AppKit in the app besides MetalUI's own window code.
@MainActor
enum SystemReduceTransparency {
    /// Whether the setting is on now.
    static var isOn: Bool { NSWorkspace.shared.accessibilityDisplayShouldReduceTransparency }

    /// One value each time any display accessibility option changes (Reduce Transparency, Increase Contrast, ...).
    static func changes() -> AsyncStream<Void> {
        AsyncStream { continuation in
            let observing = Task { @MainActor in
                let name = NSWorkspace.accessibilityDisplayOptionsDidChangeNotification
                for await _ in NSWorkspace.shared.notificationCenter.notifications(named: name) {
                    continuation.yield()
                }
                continuation.finish()
            }
            continuation.onTermination = { _ in observing.cancel() }
        }
    }
}
```
