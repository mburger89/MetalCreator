# Adopt MetalUI C14 slice 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt MetalUI C14 slice 1 (MetalUI master `e85cb07a`, PR #82, record §104), the first part of gap PERF-b: the canvas's per-node, per-wire and per-comment views skip their `content` getter while their value is unchanged.

**Architecture:** The layout memo is automatic and needs no code. `Component.equatable()` is opt-in on a component whose `Self: Equatable`: it skips `content` while the value and `@State` are unchanged, and it refuses a component that declares `@Environment` (divergence 346). Today `NodeView`, `NodeHeaderView`, `NodeRowView`, `StatusBadgeView`, `SocketLayer`, `CommentFrameView`, `StickyView` and `CommentHandleView` each read `@Environment(ThemeStore.self)`. `CanvasLayers`, the one canvas view that keeps reading it, builds the `Palette` and passes it down as a stored value; every canvas view becomes `Equatable` with all its inputs stored (the synthesized `==` covers them), and `CanvasLayers` / `NodeView` apply `.equatable()`. Proof is headless: tests read `FrameWork.contentEvaluations / contentSkips / contentRefusals` in the app's real window, and compare each incremental frame with the picture a full re-evaluation draws.

**Tech Stack:** Swift 6.2 strict concurrency, SwiftUI-like MetalUI (sibling `../MetalUI`, master `e85cb07a`), Swift Testing, `MetalUITesting` (`TestWindow`, `FrameWork`), SwiftLint.

**Spec:** `docs/metalui-gaps.md` entry PERF-b (and its summary row, and M7's measurements in `docs/verification/performance.md`); MetalUI side `../MetalUI/docs/record/104-incremental-invalidation.md` (§4 layout memo, §5 `Component.equatable()`), `../MetalUI/docs/divergences.md` row 346, `../MetalUI/docs/testing.md` (`FrameWork.contentEvaluations / contentSkips / contentRefusals`); under the parent spec `docs/superpowers/specs/2026-10-07-metalcreator-vertical-slice-design.md` with all its Errata.

## Review Focus

Failure modes the spec implies that a person using the editor would hit, most likely first. Each has a test in the task named.

1. A canvas view gains a stored property that `==` does not cover, so it goes stale after an edit (no error, just a picture that does not follow the model). Expected: adding the property fails a test until it has a variant. Test: `expectEqualityCovers` over every view's stored properties (Tasks 1 and 2).
2. Switching the colour theme while nodes, wires and comments are skipped. Expected: every canvas view repaints in the new theme, like a window that started in it. Test: `aThemeChangeEvaluatesEveryViewAndDrawsTheNewColours` (Task 3).
3. Selecting a node or a comment (and clearing the selection). Expected: only the views whose selection changed re-evaluate, none keeps a stale outline or handle. Tests: `aSelectionChangeEvaluatesOnlyTheNodesWhoseSelectionChanged`, `selectingACommentEvaluatesOnlyThatComment` (Task 3).
4. A node's evaluation state changing (wiring a profile into an Extrude). Expected: its badge, its rows and the new wire follow. Test: `aNodesBadgeFollowsItsEvaluationState` (Task 3).
5. The refusal shake (a `keyframeAnimator` inside a node's `content`) on a node that otherwise skips. Expected: it still shakes. Test: the existing `RefusalShakeWindowTests`, which must pass unchanged in the full run (Task 3); `shakes` is part of `NodeView ==`.
6. A drag of one node must not make the other nodes evaluate. Test: `draggingOneNodeEvaluatesOnlyThatNodeAndItsWires` (Task 3).
7. A canvas view that later declares `@Environment` is silently refused (evaluated every frame). Expected: a test says so. Test: `contentRefusals == 0` in `aSteadyFrameEvaluatesNoCanvasView` and the drag test (Task 3).

## User decisions

No product behaviour is left open by the spec. Two choices about how this adoption touches code are the user's; the plan is written for the recommended option of each.

1. **Existing test call sites.** The views now require their palette as a value, so seven call sites in five existing test files (`ThemeRenderTests`, `LibraryViewTests`, `GroupLookTests`, `StatusBadgeRenderTests`, `TreeDisplayTests`) gain a `palette:` argument; no assertion changes. Options: (A, recommended) require the argument, so a caller that forgets it does not compile (the bug class this change must keep out: a view silently drawing Dracula); (B) default `palette: Palette = .dracula` so the five files stay byte-identical, at the price of a canvas view that can quietly ignore the theme.
2. **`BoxSelectionView` keeps reading `@Environment(ThemeStore.self)`.** It is built only while a box is dragged, is not `.equatable()`, and converting it saves nothing. Options: (A, recommended) leave it; (B) pass it `palette` too, for the CLAUDE.md rule "canvas views take the palette by value" to have no exception.

+/// Records an issue unless `variants` holds exactly one value for each stored property of `base`, each unequal to `base`
+/// (so `==` reads that property), and `base` equals an identical copy. An `.equatable()` component skips its content

+                                            sourceLocation: SourceLocation = #_sourceLocation) {
+    let stored = Set(Mirror(reflecting: base).children.compactMap(\.label))
+    #expect(Set(variants.keys) == stored, "one variant per stored property", sourceLocation: sourceLocation)
+    #expect(base == base, "equal inputs are equal", sourceLocation: sourceLocation)
+    for (name, other) in variants {
+        #expect(other != base, "\(name) is part of ==", sourceLocation: sourceLocation)
+    }
+}

## Risks

- **Nothing is timed.** Only the content getters are saved; MetalUI's own sample put them at about 21% of the build phase, and the build recursion, layout, prepaint and paint of unchanged nodes still run. The user-visible win in milliseconds is unmeasured until an idle-Mac re-take of `Bench` (owed, recorded in `performance.md`).
- **`CanvasLayers` still evaluates on every model change** (it reads the model and is refused by design) and builds every visible node's `NodeRowModel`s and every wire's geometry each time: O(nodes) work per drag step that this slice does not remove.
- **Equality cost.** Each visited `.equatable()` view compares its value to the last one: a `Palette` is a `ThemeColors` of about 45 colours. At the fixture's scale (about 80 instances) this is microseconds; untimed.
- **Stale views if a later change breaks the contract**: a new stored property left out of a hand-written `==`, or a canvas view that starts reading `@Environment` (silently refused, so correct but slow). The tests catch both (`expectEqualityCovers`, `contentRefusals == 0`).
- **Animation state under a skipped getter.** The refusal shake's `keyframeAnimator` lives inside `NodeView.content`; MetalUI promises state and identity survive a skip (record §5, `aSkippedSubtreeKeepsItsStateAndItsIdentity`) and `RefusalShakeWindowTests` confirms it here, but a future animation that depends on the getter being re-run each frame would not move.
- **Pre-existing, not caused here:** a live theme switch leaves the viewport's cube and axis glyphs in the old colours in the headless window (they draw from `ViewportModel.theme`, which the app shell sets by another path); the new `picture` helper therefore compares only the canvas.
