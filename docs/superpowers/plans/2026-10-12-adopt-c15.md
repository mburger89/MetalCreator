## What the code reading found (read before Task 1)

- **The call is not the one the gap row spelled.** EP-b's summary row says `.anchoredOverlay(isPresented:attachmentAnchor:content:)` and `PopoverAttachmentAnchor.point`; those belong to `.popover` (ruling `OV-B`). MetalUI's chrome-less overlay is `anchoredOverlay(isPresented:at:in:anchor:content:)` on a `StyledElement` or `ProposalElementGroup`, with the point in a `CoordinateSpace` (`.global` here) and a `UnitPoint` anchor (`.topLeading`: the palette's top-left corner at the point). It reads the point fresh at every layout, flips each axis to the mirrored anchor when the content then fits, then clamps inside the window **with no margin**. The row is corrected in Task 4; this is a correction, not a gap.
- **`onGeometryChange` returns a `GeometryChangeScope`, an `ElementGroup` and not an `Element`:** it is written last in a `Component`'s `content` (a `Self`-returning decoration after it does not compile), and a bare root handed to `TestWindow` needs a `ZStack` around it (the app's roots already have one).
- **A geometry action fires only when its value changes, and runs after the build, ahead of lifecycle events (`KF-J`).** Two consequences found by running it. (a) New and Open put a fresh `ViewportModel` and `EditorModel` under the same views at the same size, so nothing would tell them; the watched values therefore carry the model's `ObjectIdentifier` (`ViewSizeReport`, `PanelPlacementReport`), pinned by `aDocumentLoadedIntoTheWindowLearnsTheSizeToo` and `aNewDocumentIsPlacedToo` (the first goes red without the identity). (b) An `onDisappear { placement = nil }` on the panel runs *after* the new mount's geometry action when the dock switches (left to bottom remounts `GraphPanel`), clobbering it; hiding the panel clears the placement in `EditorModel.setDock(_:)` instead.
- **Hover regions nest:** an outer container's `onContinuousHover(coordinateSpace: .global)` and the canvas surface's `.local` hover both fire (probed), so the canvas keeps `pointerLocation` as it was and `GraphCanvas`'s container adds `pointerWindowLocation`.
- **`Color.clear.frame(maxWidth: .infinity…)` draws one transparent rect,** so the overlay's base is an empty `ZStack` (`FloatingPaletteTests.theOverlayDrawsThePaletteAndThePanelDoesNot` still sees "nothing while closed", and no rect joins every frame).
- **An `anchoredOverlay` is published as a `popover` node** (`window.elements(role: .popover)`), whose frame is the glass's; an accessibility identifier on its content is inherited by every child, so none is used. A cold `renderFrame` does not lay a presentation out, so `PaletteOverlayTests.thePaletteIsPaintedOverEverythingWhereItWasPlaced` moves to the real window.
- **`renderFrame` runs no layout callbacks.** The tests that draw one cold frame (`PanelPlacementTests.thePanelIsDrawnWhereTheLayoutSays`, the library-drag ghost test, `BenchRenderer`) are placed with a test-support helper (`ExpectedLayout.place`), which also keeps `AppLayout`'s numbers pinned: the window tests compare the measured panel with `ExpectedLayout.graphPanelFrame` in both docks.
- **The headless viewport now has its real size,** so it frames its first scene at first layout as the app does, and `ViewportKeyRoutingWindowTests.fFramesTheViewportOver…` zooms in first so F has a framing to restore (the only existing test that changes).
- **Reachability.** A bottom-docked canvas runs to the window's right edge but sits at its bottom, so the right edge alone cannot be reached from a dock: the "flips left" test is the corner (`itFlipsLeftAtTheRightEdgeAndUpAtTheBottom`), the bottom edge alone is the left dock (`itFlipsUpAtTheBottomEdgeAndOnlyThere`), and the right edge alone is the resize test (`resizingTheWindowWhileOpenKeepsItInside`).
- **Pinch over the palette is unchanged:** C15 swallows presses, the wheel and drops on an overlay, not pinches, and a pinch over the palette still moves nothing and leaves it open (human check GI-7; `aPinchOverItMovesNothingAndItStaysOpen`).
- **Nothing in C15 failed to do what its notes promise,** so this plan logs no gap. What a person might notice: the palette is flush with the window's edge (the stopgap kept an 8-point margin; decision U2).

## Review Focus

Failure modes the spec implies that a person using the editor would hit, most likely first; each has its test (named) in the owning task.

1. **The palette must never be cut off by the window's right or bottom edge, before anything has been drawn, after a resize, and in either dock.** `PaletteOverlayWindowTests.itOpensWithItsTopLeftCornerAtThePointerWhateverTheViewportHasDrawn`, `itFlipsLeftAtTheRightEdgeAndUpAtTheBottom`, `itFlipsUpAtTheBottomEdgeAndOnlyThere`, `resizingTheWindowWhileOpenKeepsItInside` (Task 3).
2. **A press that closes the palette must still do what it was for: focus the field, move the slider, open the context menu, select the node.** `aPressIntoATextFieldClosesItAndTheFieldGetsFocus`, `aPressOntoASliderClosesItAndTheSliderStillMoves`, `aRightClickThatOpensAContextMenuClosesItAndTheMenuStillOpens`, `aPressOnTheCanvasClosesItAndSelectsWhatItHit` (Task 3).
3. **Pressing, scrolling or pinching on the palette itself must not act on the canvas, the viewport or the inspector under it, and must not close it.** `aPressOnItsOwnGlassStaysOpenAndNothingBeneathReacts`, `aScrollOverItDoesNotReachTheCanvasOrTheViewport`, `aPinchOverItMovesNothingAndItStaysOpen` (Task 3).
4. **New and Open must not leave the new document's viewport at 0 × 0 or its graph panel unplaced** (no handle labels, no culling window, no library drop). `aDocumentLoadedIntoTheWindowLearnsTheSizeToo` (Task 1), `aNewDocumentIsPlacedToo` (Task 2).
5. **Hiding the panel, bringing it back, and switching docks must leave the placement right,** or the canvas culls against a stale rectangle and a library drop lands nowhere. `hidingThePanelClearsThePlacementAndShowingItBringsItBack`, `movingTheDockMovesThePlacement`, `theLibraryMovesTheCanvasInTheMeasuredFrameToo` (Task 2).
6. **Growing the window must draw what it uncovers, and the viewport's labels and picking must follow the size.** `aGrownWindowRebuildsTheCanvasWithWhatItUncovers` (Task 2), `aResizedWindowResizesTheViewport` and `ViewSizeObservationTests` (Task 1).
7. **Tab or Space with the pointer not over the canvas must open the palette at the canvas corner, not at a stale window point.** `FloatingPaletteTests.withNoPointerOverTheCanvasItIgnoresAStaleWindowPoint` (Task 3).

## Risks

- **Rebuilds per resize.** The viewport's size and the panel's placement are tracked and written from layout, so a live-resize frame builds, lays out, writes, and builds again; before, the size reached observers one task after the draw, also a second build. PERF-b (every observed change rebuilds the whole window, C14) is the cost model; nothing was measured because the release benchmark must not be run. If the idle benchmark later shows a regression, the write can be skipped when the value is unchanged (it already is) or coalesced.
- **One frame of staleness.** An `onGeometryChange` action runs after the build, so the first build after a dock switch or a resize culls against the previous placement; `EditorModel.cullingMargin` (160 points) was already sized for "one frame of a window resize".
- **Geometry actions run ahead of lifecycle events.** Any future `onDisappear` that clears what a sibling mount's geometry action sets will clobber it; see the note in Task 2's Step 3.
- **MetalUI master moves.** It already has (now `a720fba`, PR #67; the patches apply, build and pass there too). The plan is written to `0abce86`'s `anchoredOverlay(isPresented:at:in:anchor:content:)`; its clamp has no margin (U2).
