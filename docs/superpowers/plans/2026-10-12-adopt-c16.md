## What the code reading found (read before Task 1)

- **The five rows are not five independent changes.** S5-b (a double click) is a model change with no MetalUI API to wire beyond one field. GI-a and S5-a are one change on the viewport: a tap's modifiers, and ⌘ held over a still pointer. VI-a touches every owner of per-gesture state (the viewport's drag and pinch, the canvas's press, middle pan, pinch, library drag, the panel's resize edge). GI-b needs nothing but tests: MetalUI latches the scroll and synthesizes its end, and the canvas's own scroll code already copes.
- **GI-a needs nothing on the graph canvas.** The canvas keeps its one `DragGesture(minimumDistance: 0)`: its values already carry the modifiers of the press and of every change, and a press has to be able to become a box, a wire or a move, which a `SpatialTapGesture` beside a drag cannot follow. Moving it to a tap would also lose the 3-point click threshold's meaning. The row says so; the entry keeps the canvas's shape and its comment gains the reason.
- **`onModifierKeysChanged` returns a `ModifierKeysScope`, an `ElementGroup` and not an `Element`** (like `onGeometryChange`): `ViewportView` writes it last in `content`, after `onGeometryChange`. Its action is a plain closure (not `@MainActor`) but compiles with a `[model]` capture inside a `Component`'s `content`. A scope makes the window redraw on every watched change, so the view watches ⌘ only (`ViewportModifiers.hoverMask`). Fires also with the pointer still, and reports `[]` when the window stops being key (`IF-D` item 4).
- **`DragGesture.Value.clickCount` is the press's** (`IF-C`): the same in every `onChanged` and the `onEnded`; `TestWindow.doubleClick(at:)` sends the second press with count 2. The platform honours the user's double-click speed (AppKit's `NSEvent.clickCount`; SDL's `clicks`).
- **`onCancelled` fires once, and only for a gesture that had reported a change** (`IF-E`): from `abandon()` (a press on another element), a stale button or pinch arena replaced, a `.mouseMoved` while a *button* arena is live (a lost right or middle release: AppKit and SDL send `*Dragged` while a button is held), the pinch arena on key loss, and window close. A scroll's `.cancelled` is synthesized on key loss and close (`IF-H`).
- **One hole, found by running it (new gap VI-b).** A primary press on the element the live arena already belongs to is a *continuing* press (the second press of a tap sequence, `GestureArena.press(… continuing: true)`); it fails every undecided leaf that is not a tap through `fail(_:)`, not `cancel()`. A primary drag whose release was lost and whose next press lands on the same element is therefore dropped with no callback at all. `ViewportCancelWindowTests.aPrimaryPressOnTheSameElementLeavesTheLostDragToTheNextDragValues` pins it. The viewport's `beginDragIfNeeded` (for the primary button only now) and `click(at:)` and the editor's `ensurePress` therefore **stay** as stopgaps, and the entry VI-b records it. This is why VI-a's stopgap removal is partial: the pinch guesses go, the primary-drag guess narrows, the button-arena guess goes.
- **`MetalUITesting` drives what these tests need, with two limits.** `TestWindow.scroll(at:byDeltaX:deltaY:)` sends phaseless events only, and `magnify(at:by:)` always ends its pinch; the tests send `ScrollEvent`s with phases and unfinished `MagnifyEvent`s themselves (`send(_:)` is public). Key loss is `setControlActiveState(.inactive)`; `pressModifiers(_:)` sends `.modifiersChanged` and later mouse events carry the held modifiers.
- **Window tests that relied on a clock that never moved.** `AppWindow.open` set `editor.now` to one frozen instant so any two clicks paired. With the platform's count that fixture line goes; every existing window test that double-clicks already uses `TestWindow.doubleClick(at:)`, which sends counts 1 and 2, and passed unchanged.
- **`AppInput` needs nothing.** Modifiers reach the viewport through its own view (`onModifierKeysChanged` is an element scope), not through the window's `onInput`; `GraphPanelInput.handle(_:)` still ignores `.modifiersChanged`, and its comment ("a press reads its own") stays true.
- **GI-b's `EditorModel.scrolled` fallback stays.** A `.changed` with no `.began` can still reach the canvas when the latched canvas was rebuilt mid-scroll (a document load): MetalUI then falls back to the pointer, so `aScrollThatBeganElsewhereIsTakenUpAsItIsNow` stays, with its rationale corrected.
- **The library row's drag and the panel's resize edge have the same hazard as the canvas** (a ghost, or `isResizingPanel`, outliving a dropped gesture) and are not named by VI-a; they get `onCancelled` in Task 4 because they are the same adoption and each is two lines.

## Review Focus

Failure modes the spec implies that a person using the editor would hit, most likely first; each has its test (named) in the owning task.

1. **A double click that isn't one must not open anything, and one the system counts must.** A count 2 with no first click (the first was on empty canvas, or on a frame's edge band), a ⇧ or ⌘ on either click, two different nodes, a drag between, a count 3 or 4, a click the platform counted 1 however close in time. `DoubleClickTests.clicksThatArentADoubleClickDoNothing`, `aThirdClickIsNotADoubleClickAndStartsNoPair`, `theModelAddsNoTimeOrDistanceOfItsOwn`, `CanvasDoubleClickWindowTests` (Task 1).
2. **⌘ held when the window stops being key, or with the pointer elsewhere or mid-drag, must not leave the sketch's inference suppressed or replay a stale hover.** `ViewportModifiersWindowTests.losingKeyReleasesCommandAtTheTool`, `shiftAndOptionAreNotWatched`, `ViewportToolTests.aModifierWithNoPointerOverTheViewOrDuringADragTellsTheToolNothing` (Task 2).
3. **A dropped gesture must end where it was, once, and the next gesture must be fresh:** a cancel for a button that isn't dragging, twice, or with no drag; a pinch cut short followed by a pinch at the same spot; a lost right or middle release; and the one case MetalUI still drops silently (VI-b). `ButtonDragTests.aCancelOfAnotherButtonOrOfNothingChangesNothing`, `ViewportCancelWindowTests` (Task 3).
4. **A cancelled canvas press must not click, select, open a double click, leave a wire, ghost or half box behind, or leak its ⇧ into the next press.** `PointerCancelTests`, `CanvasCancelWindowTests`, `PressModifierTests.aLostPressTakesItsModifiersWithIt` (Task 4).
5. **A scroll or glide cut short, or drifting off its element, must leave nothing stuck:** a ⌘-zoom's "ignore the glide" flag after key loss, a glide that jumps to the viewport or the library, a wheel step after a glide going to the wrong element. `ScrollLatchWindowTests` (Task 5).

```swift
import CreatorGeometry
import CreatorGraph
import MetalUI
import MetalUITesting
import Testing
@testable import CreatorApp
@testable import CreatorEditor

/// A double click on the graph canvas, through the app's real window: the count is the platform's (MetalUI C16,
/// `DragGesture.Value.clickCount`, gap S5-b), so what the canvas does with a double click follows the window's clicks, not
/// a timer of the editor's. `TestWindow.doubleClick(at:)` sends the second press with click count 2, as AppKit does.
@MainActor
struct CanvasDoubleClickWindowTests {
    func open() async throws -> (app: AppWindow, sketch: Node, spot: Point<Pixels>) {
        var builder = GraphBuilder()
        let box = builder.sketchedBox()
        let app = try await AppWindow.open(builder.graph)
        return (app, box.sketch, app.point(inCanvas: Vector2(60, 40)))
    }

    @Test func aDoubleClickOnTheSketchNodeOpensItsSketch() async throws {
        let (app, sketch, spot) = try await open()
        app.window.doubleClick(at: spot)
        await app.model.settle()
        #expect(app.model.sketch?.node == sketch.id)
    }

    @Test func twoSeparateClicksDoNot() async throws {
        let (app, sketch, spot) = try await open()
        app.window.click(at: spot)
        app.window.click(at: spot)
        await app.model.settle()
        #expect(app.model.sketch == nil && app.editor.inspectorRequest == nil)
        #expect(app.editor.selection == [sketch.id])
    }

    /// However slow the user's double click is, the platform's count decides: the editor keeps no time of its own.
    @Test func aSlowDoubleClickTheSystemCountsStillOpensIt() async throws {
        let (app, sketch, spot) = try await open()
        app.window.click(at: spot)
        app.window.advance(by: 5)
        app.window.send(.mouseDown(MouseEvent(position: spot, clickCount: 2)))
        app.window.send(.mouseUp(MouseEvent(position: spot, clickCount: 2)))
        app.window.tick()
        await app.model.settle()
        #expect(app.model.sketch?.node == sketch.id)
    }

    @Test func aDoubleClickWithShiftHeldOnlyExtendsTheSelection() async throws {
        let (app, _, spot) = try await open()
        app.window.doubleClick(at: spot, modifierFlags: .shift)
        await app.model.settle()
        #expect(app.model.sketch == nil)
    }
}
```
