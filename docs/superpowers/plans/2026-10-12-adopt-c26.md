**Architecture:** MetalUI C26 changes no API. A primary press that finds its arena still pressing is a lost release: that arena is abandoned through `cancel()` (a drag that had reported gets `onCancelled` exactly once), a fresh arena forms for the new press (minimum distance included), a late release cancels nothing again, and `GestureArena.press(continuing: true)` also cancels a reported drag it fails. MetalCreator already routes `onCancelled` to `ViewportModel.dragCancelled(button:)` and `EditorModel.pointerCancelled()` (plan `2026-10-12-adopt-c16`). ## Review Focus

The inputs and conditions the spec implies and a person would meet, most likely first. Each has its pinning test in the task that owns the code.

1. **A handle edit whose release was lost** ends at the next press on the viewport: `.ended` is reported exactly once (not again by a late release), the value it got to is kept as one undo step. `ContinuingPressCancelWindowTests.aHandleEditWhoseReleaseWasLostEndsAtTheNextPressOnTheViewport` (Task 1).
2. **The press that ended the lost drag must start a normal drag**: nothing moves under the 5-point minimum distance, then the orbit moves from the new press, not from the lost one; the late release cancels nothing again. `ViewportCancelWindowTests.aPrimaryPressOnTheSameElementCancelsTheLostDragAndTheNewDragStartsFresh` (Task 1).
3. **The canvas's move and box**: a box whose release was lost puts back the selection it began with at the next press and the next box starts from the new press after the 3-point threshold; a node move stays where it got to as one undo step and the new press is an ordinary click. `aBoxWhoseReleaseWasLostIsCancelledByTheNextPressOnTheCanvas`, `aNodeMoveWhoseReleaseWasLostEndsAtTheNextPressOnTheCanvas` (Task 1).
4. **A real double click fires nothing spurious**: over the viewport it reports two clicks, settles nothing, ends no drag (`aDoubleClickOverTheViewportCancelsNothing`, Task 1); on the canvas, where the count comes from `DragGesture.Value.clickCount == 2`, it still opens a Sketch node and edits a note or frame (`CanvasDoubleClickWindowTests`, unchanged, run in Task 1 Step 4). `aDoubleClickOverTheViewportCancelsNothing` is a regression guard: it passes on MetalUI before and after C26.
5. **A primary click while a right or middle button is held**: still ends that held drag where it was (it is not a lost release), while a click never ends a primary drag any more. `ButtonDragTests`/`ViewportInputTests.aClickWhileAnotherButtonsDragIsUnderWayEndsItAndHoversAgain`, `aCancelledPrimaryDragLeavesTheNextPressAFreshOrbit` (Task 2).

One limit stays and is pinned, not hidden: a plain pointer move does not end a lost left drag (new gap VI-c; `aPlainMoveDoesntEndALostPrimaryDragOnlyTheNextPressDoes`).

## Key decisions (made in this plan; the user decisions are listed in the return, not repeated here)

- **Order: tests before removal.** The window tests assert the state *right after the second press, before any value of that press arrives*. A stopgap acts only on later values (`beginDragIfNeeded`, `ensurePress`) or on a click, so those assertions can only pass if MetalUI cancelled the drag. They are green with the stopgaps in place (Task 1), which is the proof the task asks for, and stay green when the stopgaps go (Task 2). Against MetalUI `3fce05f` (C26's parent) five of the new tests are red.
- **`beginDragIfNeeded` keeps its other-button branch.** VI-b's stopgap is the `|| state.start != start` half (a primary value from another press of the same button). The `state.button != .primary` half is `CI-F` item 3 (a primary press while a right or middle button is physically held) and is not a lost release; it stays.
- **`click(at:)` ends a right or middle drag, not a primary one.** The entry says to remove "the drag-ending line"; only its primary case is VI-b's. Removing the whole line would let a held right-button orbit run on through a left click, a behaviour change nobody asked for. This departs on purpose from the entry's literal text ("remove the drag-ending line"); deleting the whole line is the alternative. User decision U1 covers it (recommended: keep the narrowed line).
- **No model guard is kept** for a direct model call that skips `onCancelled`. The only callers of `dragChanged`/`dragEnded`/`click(at:)` are `ViewportView`'s gestures and of `pointerDragged`/`pointerReleased` are `GraphPanelInput`'s, and MetalUI cancels first. A model-only caller that skipped the cancel would merely continue the press in progress (no crash, nothing leaks: its hit, modifiers and interaction stay consistent with its start). Two new model tests pin that contract so a stopgap cannot creep back (user decision U2).
- **`aPrimaryPressOnTheSameElementLeavesTheLostDragToTheNextDragValues` is inverted in place**, renamed `aPrimaryPressOnTheSameElementCancelsTheLostDragAndTheNewDragStartsFresh`. `PressModifierTests.aLostPressTakesItsModifiersWithIt` becomes `aCancelledPressTakesItsModifiersWithIt` (the press is cancelled, as MetalUI now does). The three model tests that exercised the stopgaps directly (`ButtonDragTests.aPrimaryDragWhoseReleaseWasLostEndsWhenTheNextPressDrags`, `ViewportInputTests.aClickWhileADragIsUnderWayEndsItAndHoversAgain`, `PointerTests.aPressThatNeverEndedDoesNotLeakIntoTheNext`) are rewritten to the C26 sequence.
- **Human checks: a new group C26** (C26-1 mirrors MetalUI's `GC1`, C26-2 mirrors `GC2`), and C16-5 points to it.
- **A new gap, VI-c**, found while writing the tests: MetalUI cancels a right or middle arena at the next plain move but not the primary arena (its ruling `GC-C`), so after a lost left release the closed hand and the unsettled camera stay until the next press. Logged, pinned by a test, not worked around, sent to the MetalUI session.
- No erratum to the parent spec or the two feature specs: no statement in them depends on the stopgaps (checked by search), and user-visible behaviour is only better.

````swift
import CreatorGeometry
import CreatorGraph
import MetalUI
import MetalUITesting
import Testing
@testable import CreatorApp
@testable import CreatorEditor
@testable import CreatorViewport

/// A primary press that arrives while the arena is still pressing (the release went to Mission Control or a native menu) is
/// a lost release to MetalUI C26 (`GC-B`, `GC-C`): it abandons that arena through `cancel()`, so a drag that had reported gets
/// `onCancelled` once, and a fresh arena forms for the new press. These run the app's real window, press on the same element
/// twice, and look before any drag value of the second press arrives, which is the proof that no model stopgap is needed
/// (docs/metalui-gaps.md VI-b): the viewport's and the canvas's drag, a handle edit's end and the closed hand end at the press.
@MainActor
struct ContinuingPressCancelWindowTests {
    /// Above the graph panel with the default dock (corrected 2026-10-30: the default dock is left, not bottom): the viewport.
    func spot(_ dx: Float, _ dy: Float = 0) -> Point<Pixels> {
        Point(x: Pixels(700 + dx), y: Pixels(300 + dy))
    }

    func press(_ app: AppWindow, at point: Point<Pixels>) {
        _ = app.window.send(.mouseDown(MouseEvent(position: point)))
        app.window.tick()
    }

    func move(_ app: AppWindow, to point: Point<Pixels>) {
        _ = app.window.send(.mouseDragged(MouseEvent(position: point)))
        app.window.tick()
    }

    func release(_ app: AppWindow, at point: Point<Pixels>) {
        _ = app.window.send(.mouseUp(MouseEvent(position: point)))
        app.window.tick()
    }

    // MARK: - The viewport

    /// A handle edit whose release was lost ends at the next press on the viewport, with the phase `.ended` reported once and
    /// the value it got to kept as one undo step; the press that ended it then starts an ordinary orbit.
    @Test func aHandleEditWhoseReleaseWasLostEndsAtTheNextPressOnTheViewport() async throws {
        var builder = GraphBuilder()
        let box = builder.box(distance: 10)
        let app = try await AppWindow.open(builder.graph)
        let viewport = app.model.viewport
        app.editor.selection = [box.extrude.id]
        await app.model.settle()
        app.redraw()
        let handle = try #require(viewport.handles.first)
        let knob = try #require(CameraMath.project(handle.knob, viewport.pose, size: viewport.viewSize)).point
        var phases: [HandleDragPhase] = []
        let previous = viewport.events.handleChanged
        viewport.events.handleChanged = { phases.append($2); previous($0, $1, $2) }
        let start = Point(x: Pixels(Float(knob.x)), y: Pixels(Float(knob.y)))
        press(app, at: start)
        for step in 1...4 {
            move(app, to: Point(x: Pixels(start.x.value), y: Pixels(start.y.value - Float(step) * 8)))
        }
        #expect(viewport.activeDragMode == .handle(handle.id) && phases.last == .changed)
        let edited = try #require(app.model.document.graph.nodes[box.extrude.id]?.inputValues["distance"])
        #expect(edited != .number(10), "the drag moved the value")
        press(app, at: spot(100, 100))
        #expect(viewport.activeDragMode == nil && !viewport.isPointerDown)
        #expect(phases.filter { $0 == .ended }.count == 1, "the edit's end came from the cancel, once")
        release(app, at: spot(100, 100))
        #expect(phases.filter { $0 == .ended }.count == 1, "the late release ends nothing again")
        #expect(app.model.document.graph.nodes[box.extrude.id]?.inputValues["distance"] == edited, "the edit is kept")
        app.model.document.undo()
        #expect(app.model.document.graph.nodes[box.extrude.id]?.inputValues["distance"] == .number(10), "as one undo step")
    }

    /// Gap VI-c: MetalUI cancels a button arena at the pointer's next plain move (`IF-F` item 3) but not the primary arena (its
    /// ruling `GC-C` leaves the bare move alone, as SwiftUI does), so a lost primary release leaves the drag, its closed hand and
    /// its unsettled camera in place until the next press ends them. When MetalUI cancels on the move, invert this.
    @Test func aPlainMoveDoesntEndALostPrimaryDragOnlyTheNextPressDoes() async throws {
        let app = try await AppWindow.open()
        let viewport = app.model.viewport
        app.window.hover(at: spot(0))
        press(app, at: spot(0))
        for step in 1...3 { move(app, to: spot(Float(step) * 10)) }
        _ = app.window.send(.mouseMoved(MouseEvent(position: spot(60, 20))))
        app.window.tick()
        #expect(viewport.isPointerDown && viewport.cursor == .grabbing, "gap VI-c: the move ended nothing")
        press(app, at: spot(60, 20))
        #expect(!viewport.isPointerDown && viewport.cursor == nil, "the press did")
    }

    /// A real double click (platform count 2) over the viewport fires no cancel: it settles nothing, ends no drag and reports
    /// two clicks, as it did before C26 (`GC2`: the continuing branch is kept for a press that finds the arena released).
    @Test func aDoubleClickOverTheViewportCancelsNothing() async throws {
        let app = try await AppWindow.open()
        let viewport = app.model.viewport
        var settled = 0
        var clicks = 0
        let previous = viewport.events.cameraSettled
        viewport.events.cameraSettled = { settled += 1; previous($0) }
        let previousClick = viewport.events.clicked
        viewport.events.clicked = { clicks += 1; previousClick($0) }
        app.window.doubleClick(at: spot(0, 60))
        #expect(settled == 0 && !viewport.isPointerDown)
        #expect(clicks == 2, "both clicks arrive as clicks")
    }

    // MARK: - The canvas

    func canvas(_ app: AppWindow, _ x: Double, _ y: Double = 120) -> Point<Pixels> {
        app.point(inCanvasView: Vector2(x, y))
    }

    /// A box whose release was lost is cancelled by the next press on the canvas: the selection it began with is put back
    /// before any value of the new press arrives, the late release is that press's own click, and the new drag, a box again,
    /// starts from the new press after the canvas's own 3-point threshold.
    @Test func aBoxWhoseReleaseWasLostIsCancelledByTheNextPressOnTheCanvas() async throws {
        var builder = GraphBuilder()
        let box = builder.box()
        let app = try await AppWindow.open(builder.graph)
        let editor = app.editor
        editor.selection = [box.output.id]
        let from = canvas(app, 600, 160)
        press(app, at: from)
        move(app, to: canvas(app, 760, 220))
        guard case .boxSelecting? = editor.interaction else {
            Issue.record("expected a box")
            return
        }
        #expect(editor.selection != [box.output.id], "the box replaced the selection")
        press(app, at: canvas(app, 620, 170))
        #expect(editor.interaction == nil, "the cancel ended the box at the press")
        #expect(editor.selection == [box.output.id], "and put the selection back")
        move(app, to: canvas(app, 621, 170))
        #expect(editor.interaction == nil, "1 point is under the canvas's 3-point threshold")
        move(app, to: canvas(app, 700, 210))
        guard case .boxSelecting(let origin, _, _, _)? = editor.interaction else {
            Issue.record("expected a fresh box")
            return
        }
        #expect(origin == editor.transform.toCanvas(Vector2(620, 170)), "from the new press, not the lost one")
        release(app, at: canvas(app, 700, 210))
        #expect(editor.interaction == nil)
    }

    /// A node move whose release was lost stays where it got to and its undo step ends at the next press on the canvas; that
    /// press is a plain click on empty canvas, which clears the selection.
    @Test func aNodeMoveWhoseReleaseWasLostEndsAtTheNextPressOnTheCanvas() async throws {
        var builder = GraphBuilder()
        let sketched = builder.sketchedBox()
        let app = try await AppWindow.open(builder.graph)
        let editor = app.editor
        let node = sketched.sketch.id
        let origin = try #require(app.model.document.graph.nodes[node]?.position)
        let spot = app.point(inCanvas: Vector2(60, 40))
        press(app, at: spot)
        move(app, to: Point(x: Pixels(spot.x.value + 40), y: Pixels(spot.y.value)))
        guard case .moving? = editor.interaction else {
            Issue.record("expected a move")
            return
        }
        let moved = try #require(app.model.document.graph.nodes[node]?.position)
        #expect(moved != origin)
        let empty = canvas(app, 20, 200)
        press(app, at: empty)
        #expect(editor.interaction == nil, "the move ended at the press")
        #expect(app.model.document.graph.nodes[node]?.position == moved, "and stayed where it got to")
        release(app, at: empty)
        #expect(editor.selection.isEmpty, "the new press, released, is a click on empty canvas")
        app.model.document.undo()
        #expect(app.model.document.graph.nodes[node]?.position == origin, "the lost move was one undo step")
    }
}
````
