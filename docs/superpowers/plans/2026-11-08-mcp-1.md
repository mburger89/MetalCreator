# MCP-1: the MetalCreator MCP server — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An MCP client (Claude Code, the Claude desktop app) reads and edits the document open in the running MetalCreator through a stdio bridge and a local socket, every edit one named undo step.

**Architecture:** A portable library `CreatorMCP` holds JSON, JSON-RPC, the tools and their handlers over a `@MainActor` protocol `DocumentSession`, plus the local socket code and the bridge's logic. `DocumentModelSession` (in `CreatorMCP`) implements the session over a `DocumentModel` and is what every tool test drives; `AppDocumentSession` (in `CreatorApp`) wraps it with the app's modes, alerts, files and export. `MCPService` (in `CreatorApp`) owns the listener, the switch and the chip; the executable `metalcreator-mcp` is a thin `main.swift` over `MCPBridge`.

**Tech Stack:** Swift 6.4 strict concurrency, Foundation (`JSONSerialization`/`JSONEncoder` are already used in portable targets), POSIX sockets (`Darwin`/`Glibc`) and Winsock (`WinSDK`) behind `#if os(...)`, Swift Testing, MetalUI for the menu item and chip.

**Spec:** `docs/superpowers/specs/2026-11-08-mcp-server-design.md` (approved 2026-11-08). MCP-2 (pictures, spec §5) is a later plan.

## Global Constraints

- Swift 6 strict concurrency; every read and edit runs on the main actor; values crossing threads are `Sendable` (`JSONValue`, `Data`, `String`). No `@unchecked Sendable` or `nonisolated(unsafe)` to silence a diagnostic.
- No new external package dependencies. JSON-RPC is our own subset: `initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`, `resources/list`, `resources/read`.
- Portable everywhere: no Apple-only import outside `#if canImport(…)`/`#if os(…)`; socket code is one small file per OS family.
- Numbers are stored units, never converted: lengths millimetres, angles degrees (`ValueUnit`), counts integers.
- Undo names come from `UndoName` constants and functions, never from client text; no numbers in names. A client's edits never coalesce (`coalescingKey: nil`), and each is followed by `document.endCoalescing()`.
- No unsaved document is discarded and no file overwritten unless the call says `discard_unsaved: true` / `overwrite: true`. Paths must be absolute; a relative path is refused ("Paths must be absolute.").
- Nothing listens on a network port. The socket file has permissions 0600 and its folder 0700 where the platform has them.
- The file format doesn't change; nothing MCP is saved in `.mcgraph`.
- The server runs only in the normal windowed launch, never under `--self-test`, `--smoke-test` or headless.
- Tool-error sentences are in the app's voice (full sentences, as node messages are), returned as a tool result with `isError: true`. Malformed JSON-RPC gets JSON-RPC errors (-32700 parse, -32600 invalid request, -32601 method not found, -32602 invalid params).
- The suite rules: 13 "Test run with" lines on macOS, Linux and Windows once `CreatorMCPTests` exists; none may print "recorded an issue" or "failed after". `swiftlint lint --strict` reports zero violations.
- Tests are Swift Testing. Run `swift test --filter CreatorMCPTests` (and `CreatorAppTests` for app tasks) before each commit; Linux via `scripts/linux-test.sh test --filter CreatorMCPTests` in Tasks 6 and 7.

## Review Focus

1. A client sends its next request before the previous edit has settled (pipelined lines): requests are handled strictly one at a time in arrival order and responses come back in that order (Task 6 test `pipelinedRequestsAnswerInOrder`).
2. The bridge or client disappears mid-request: the server drops the connection, the chip goes off, and the listener accepts the next client (Task 6 `clientVanishingMidRequestFreesTheServer`, Task 8 `chipFollowsConnection`).
3. Two nodes share a name: name addressing refuses with "Two nodes are called “Box”; use the node's ID." rather than picking one (Task 2 `ambiguousNameIsRefused`).
4. A line that is not JSON, not UTF-8, or longer than 16 MiB: a parse error for the first two with the connection kept; the oversized line closes the connection (Task 6 `oversizedLineClosesTheConnection`, Task 1 `garbageGetsParseError`).
5. The person presses New or opens a file while a client is connected: the session follows the app's current document, and an ID from the old document is "There's no node with ID …" (Task 8 `sessionFollowsReplacedDocument`).

**Interfaces:**
- `SocketPath.default(environment: [String: String] = ProcessInfo.processInfo.environment) -> URL`: macOS `~/Library/Application Support/MetalCreator/mcp.sock`; Linux `$XDG_RUNTIME_DIR/metalcreator/mcp.sock`, else `/tmp/metalcreator-<uid>/mcp.sock`; Windows `%LOCALAPPDATA%\MetalCreator\mcp.sock`. `SocketPath.prepareFolder(_ url: URL) throws(SocketProblem)`: creates the folder 0700 (POSIX), refuses one owned by another user or wider than 0700 ("The folder for AI connections isn't private: \(path).").
- `public final class LocalSocket: Sendable` (holds only an immutable descriptor/`SOCKET`): `static func listen(at: URL) throws(SocketProblem) -> LocalSocket` (bind, chmod 0600, listen backlog 1), `static func connect(to: URL) throws(SocketProblem) -> LocalSocket`, `func accept() throws(SocketProblem) -> LocalSocket` (blocking), `func read(into: inout [UInt8]) -> Int`, `func write(_ data: Data) -> Bool`, `func close()`. Paths over the platform's `sun_path` limit are refused ("The path for AI connections is too long.").
- `LineReader`: splits on "\n", strips a trailing "\r", caps a line at 16 MiB (then reports `.tooLong`).
- `public final class MCPListener: Sendable`: `init(path: URL, handle: @escaping @Sendable (Data, @escaping @Sendable (Data) -> Void) async -> Void, connectionChanged: @escaping @Sendable (Bool) -> Void)`; `func start() throws(SocketProblem) -> StartResult` where `enum StartResult { case listening, inUse }` — it first tries `connect`: success → `.inUse` (closes it, does not touch the file); refused → removes the stale file and listens. The accept loop runs on its own `Thread`; one connection at a time; each line is awaited before the next is read (so responses keep order); `stop()` closes the socket and removes the file. `MCPService` (Task 8) passes a `handle` that hops to the main actor and calls `MCPServerCore.handle`.
