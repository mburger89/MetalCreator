## Review Focus

The spec says what the labels show and not how wide any string is; these are the inputs most likely to bite, most likely first. Each has a test in the task that owns the code.

1. **A string the old 7-points-a-character rule got wrong in either direction** (ten capital Ws, ten narrow letters): the wide one must get a wider box than the old estimate, the narrow a tighter one, equal to the laid-out frame. Task 1, `TextMeasureWindowTests.aWideStringGetsAWiderLabelBoxThanTheOldEstimateGave`, `aMeasuredTextIsTheFrameALaidOutTextGets`; Task 2, `theChipsAreSizedByTheSameMeasure`.
2. **A width that is not a whole number** (the measure is unrounded; a laid-out frame is rounded): the box rounds up so the text never wraps for want of a fraction. Task 1, `OverlayLabelTests.theBoxIsTheMeasuredWidthPlusPaddingAtEachSide`; Task 2, `ChipMeasureTests.theInferenceChipFollowsTheMeasureNotTheCharacterCount`.
3. **An empty text:** a box of padding only, no crash, no division. Task 1, the same test (`PlacedLabel.box(of: "")`).
4. **A label that is in the view only because its text is wide** (the anchor sits just left of the view): culling uses the measured box, not a character count. Task 1, `aWideTextReachingIntoTheViewIsKeptAndANarrowOneAtTheSameAnchorIsNot`.
5. **The font the measure uses differing from the font the label is drawn in** (they must both be `.caption`): every glyph lies inside the box in a real rendered frame, for the dimension labels, the handle labels and the readout chip. Task 1, `OverlayLabelTests.theViewDrawsEachLabelsTextInsideItsBox`, `HandleLabelTests.theViewDrawsTheValueInsideItsBox`; Task 2, `SketchViewTests.theChipHoldsItsText`, `InferenceGlyphTests` (the glyph test).

## What the code reading found (read before Task 1)

- **Three estimates, all the same rule.** `PlacedLabel.size(of:)` (7 points a character + 6 padding each side, height 20), `ReadoutChip.init` (7 + 8 padding, height 22) and `InferenceChip.init` (the readout's constants). A fourth site is a hard-coded box: the handle labels' 96 x 18 frame in `ViewportView+Parts.swift` (it clips a text wider than 96 points and left-aligns shorter ones). The triad's axis names have a fixed 16 x 18 box for one capital letter: a position, not a text-length estimate; it stays (user decision U2). A grep of `Sources` for `text.count` multiplied by a width and for `characterWidth` finds only the three.
- **The measurer lives in the view environment.** `@Environment(\.textMeasurer)` works in a `Component`'s body, and traps (`preconditionFailure`, GT-D) when read from a bare `EnvironmentValues()`, so no model can hold one. The models take a `TextMeasure` per call instead; nothing is stored, so nothing is stale after a theme or font change and no write happens in a body.
- **`TextMeasurer` values are usable outside the body that read them** (the box holds the frame's text system and an environment copy; `resolve` and `measure` are `@MainActor` and need no frame). That is what lets `TextMeasure.real()` capture one from a `renderFrame` and use it in a test, and the models call the closure from their own methods.
- **`measure(in:)` is unrounded, a laid-out frame is rounded** (divergence 296, GT-I; testing.md: "within one point"). Boxes round the width up to a whole point plus padding.
- **Heights stay fixed** (label 20, chip 22, handle 18): they are layout constants, the line height of `.caption` is the same for every string, and the existing look is unchanged (user decision U1).
- **`ReadoutChip.init` and `InferenceChip.init` become `@MainActor`** (the measure is `@MainActor`, like MetalUI's). Every caller is a `@MainActor` model or test already.
- **`ViewportView.stack` is `static` and takes `measure:`.** `ViewportView` is a `Component` and reads the environment; `stack` is also the place the viewport's label loops are written inline (gap M4-b), which stays.
- **Test ripple.** About 40 call sites of `ReadoutChip(`, `InferenceChip(`, `.readoutChip`, `.inferenceChip`, `handleLabels()` and `overlayLabels()` in existing tests need a measure. They are edited by two small scripts (below) rather than by hand; tests that only compare a model's chip with a chip built the same way use `.fake`, the ones that compare with a rendered frame use `.real()`.
- **MetalUI's `TimelineView(.animation)` is on `../MetalUI` master** (api-overview "Animation": C9). It is the remedy for M4-b's second half (labels hidden while the camera animates). It is not in C23 and not adopted here (user decision U3); the docs say so.

```swift
// Test fixture file: the two measures the tests place labels and chips with.
import CreatorViewport
import MetalUI
import MetalUIText

/// Captures the measurer a component reads from its environment.
@MainActor
final class MeasurerBox {
    var measurer: TextMeasurer?
}

private struct MeasurerProbe: Component {
    let box: MeasurerBox
    @Environment(\.textMeasurer) var measurer

    var content: some ElementGroup {
        box.measurer = measurer
        return Spacer()
    }
}

extension TextMeasure {
    /// A deterministic measure for model tests: 6 points a character and 12 points tall, which differs from the removed
    /// 7-points-a-character estimate, so a test that passes proves the measure was used.
    static var fake: TextMeasure { TextMeasure { text in ViewportSize(width: Double(text.count) * 6, height: 12) } }

    /// MetalUI's real measure, as `MetalUI.TextMeasurer` gives it in a frame over CoreText (the text system the window
    /// draws with). For tests that compare a model's boxes with the text a rendered frame draws.
    @MainActor
    static func real() throws -> TextMeasure {
        let box = MeasurerBox()
        _ = renderFrame({ ZStack { MeasurerProbe(box: box) } }, size: Size(width: Pixels(100), height: Pixels(100)),
                        scaleFactor: 2, textSystem: CoreTextTextSystem(), atlas: GlyphAtlas(width: 256, height: 256))
        guard let measurer = box.measurer else { throw MeasurerNotCaptured() }
        return TextMeasure(measurer)
    }
}

struct MeasurerNotCaptured: Error {}
```

```swift
import MetalUI
import MetalUITesting
import Testing
@testable import CreatorViewport

/// MetalUI C23's `@Environment(\.textMeasurer)` through a real window (MetalUI's `docs/testing.md`, "Measuring text"): a
/// component reads the measurer in its body, `TextMeasure` wraps it, and the box the models place equals the frame the
/// laid-out text gets, where the removed 7-points-a-character estimate was too narrow for wide letters and too wide for
/// narrow ones (gap S5-c).
@MainActor
struct TextMeasureWindowTests {
    /// Reads the measurer from its environment, as a component does, and lays out the two strings the tests compare with.
    struct Probe: Component {
        let box: MeasurerBox
        @Environment(\.textMeasurer) var measurer

        var content: some ElementGroup {
            box.measurer = measurer
            return VStack(spacing: Pixels(0)) {
                Text("WWWWWWWWWW").font(.caption).id("wide")
                Text("iiiiiiiiii").font(.caption).id("narrow")
            }
        }
    }

    /// What the removed stopgap gave a label box: 7 points a character and 6 at each side.
    func oldLabelEstimate(_ text: String) -> Double { Double(text.count) * 7 + 2 * 6 }

    /// What the removed stopgap gave a readout chip: 7 points a character and 8 at each side.
    func oldChipEstimate(_ text: String) -> Double { Double(text.count) * 7 + 2 * 8 }

    func open() throws -> (window: TestWindow, measure: TextMeasure) {
        let box = MeasurerBox()
        let window = try TestWindow { ZStack { Probe(box: box) } }
        guard let measurer = box.measurer else { throw MeasurerNotCaptured() }
        return (window, TextMeasure(measurer))
    }

    @Test func aMeasuredTextIsTheFrameALaidOutTextGets() throws {
        let (window, measure) = try open()
        for (id, text) in [("wide", "WWWWWWWWWW"), ("narrow", "iiiiiiiiii")] {
            let laid = try window.frame(ofID: id)
            #expect(abs(measure(text).width - Double(laid.size.width.value)) < 1, "\(text): the measure is the frame (rounded)")
            // The boxes' heights are fixed (user decision U1): a font change that made a line taller must fail here, not clip.
            #expect(measure(text).height <= HandleLabel.height, "\(text): a line fits the handle label's fixed box")
            #expect(measure(text).height <= PlacedLabel.height, "\(text): a line fits the dimension label's fixed box")
        }
    }

    @Test func aWideStringGetsAWiderLabelBoxThanTheOldEstimateGave() throws {
        let (_, measure) = try open()
        let wide = PlacedLabel.box(of: "WWWWWWWWWW", measuring: measure)
        #expect(wide.width > oldLabelEstimate("WWWWWWWWWW"), "ten capital Ws advance more than 7 points each")
        let narrow = PlacedLabel.box(of: "iiiiiiiiii", measuring: measure)
        #expect(narrow.width < oldLabelEstimate("iiiiiiiiii"), "ten narrow letters need less than 7 points each")
        #expect(wide.width > narrow.width)
    }
}
```

```python
import re, sys
root = sys.argv[1]

def read(path): return open(f"{root}/{path}").read()
def write(path, s): open(f"{root}/{path}", "w").write(s)

def add_measure_to_calls(s, ctor, arg):
    """Appends `, measuring: arg` before the closing paren of every `ctor(` call."""
    out, i = [], 0
    pattern = re.compile(r"(?<![A-Za-z])" + ctor + r"\(")
    while True:
        m = pattern.search(s, i)
        if not m:
            out.append(s[i:]); break
        depth, j = 1, m.end()
        while depth:
            depth += {"(": 1, ")": -1}.get(s[j], 0)
            j += 1
        out.append(s[i:j - 1] + f", measuring: {arg}" + ")")
        i = j
    return "".join(out)

def wrap_long_lines(s, arg):
    """Moves `measuring: arg` to a line of its own where appending it pushed a line past SwiftLint's 140 columns."""
    out = []
    for line in s.split("\n"):
        needle = f", measuring: {arg}"
        if len(line) > 140 and needle in line:
            cut = line.rindex(needle)
            indent = " " * (len(line) - len(line.lstrip()) + 8)
            line = line[:cut] + ",\n" + indent + line[cut + 2:]
        out.append(line)
    return "\n".join(out)
```

## User decisions

The plan is written for the recommended default of each.

- **U1. Box heights.** Options: (a) keep the fixed heights (label 20, chip 22, handle 18), measured width only; (b) height = the measured line height + padding. Recommended (a): `.caption` has one line height for every string, nothing is clipped vertically today, and the look stays as signed off in S5c-5 and the chip checks.
- **U2. The triad's axis letters.** Options: (a) keep the fixed 16 x 18 box centred on the axis tip; (b) measure "X"/"Y"/"Z" as well. Recommended (a): a single capital letter is far narrower than 16 points, the box is a position and not a text-length estimate, and measuring would add a third `triadLabels(measuring:)` signature for no visible change.
- **U3. Labels while the camera animates.** MetalUI master has `TimelineView(.animation)` (C9, M4-b's second half), which would let the labels follow the 250 ms Look At instead of being hidden. Options: (a) leave it hidden and say so in the docs (this plan); (b) adopt `TimelineView` for the label overlays in this plan; (c) a separate plan. Recommended (c): it changes behaviour that `OverlayLabelTests.labelsOutsideTheViewOrOfAnEmptyViewOrDuringAnAnimationAreLeftOut` pins and the spec's errata state, is independent of measuring, and wants its own human check.
- **U4. Rounding.** Options: round the measured width up to a whole point (this plan); use it unrounded. Recommended: up, since a laid-out frame is rounded (divergence 296) and a box a fraction too narrow would wrap its text.
