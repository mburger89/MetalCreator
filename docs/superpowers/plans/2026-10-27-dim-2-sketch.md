## Decisions this plan takes (spec, saved data or what the user sees)

1. **Orientation is the kind, not a field.** Horizontal and vertical are `DimensionKind` cases (overview); `SketchDimension` gains only `labelPoint: Vector2?`. A placed dimension keeps its kind; dragging its label later never changes it.
2. **Nothing reaches the document before the placing click.** Return in the box solves the pending dimension in the editor (the geometry moves on screen, spec §7) but the document gets one "Add Dimension" step only when the click places it. Esc in the box, Esc while placing, a tool change, Done, undo or reload all drop the pending dimension and put the geometry back.
3. **A typed value locks the orientation.** If Return committed a value different from the measured one, moving the pointer while placing no longer switches horizontal/vertical/aligned (that would move the geometry). With an untouched Return the orientation follows the pointer and the value is each orientation's measurement (nothing moves).
4. **Placement rule.** For two points `a`, `b` and pointer `q` in plane coordinates: `q.x` inside `[min x, max x]` and `q.y` outside `[min y, max y]` → horizontal; the reverse → vertical; otherwise aligned. When `|a.x − b.x|` or `|a.y − b.y|` is under 1e-6 mm the pair is already axis-aligned and the dimension stays aligned (its original kind).
5. **Picking (Fusion's rule; spec §4.3 "Picking a circle alone still gives its diameter").** A circle or arc first pick at once shows its diameter (circle) or radius (arc) following the pointer as a pending dimension (`PendingDimension.Phase.picked`); a click on empty space, or on the same circle, keeps that diameter/radius and opens its value box; a second circle, arc or point turns it into a centre distance (box opens). Right-click while placing still toggles Radius/Diameter (Task 8). Two lines within 0.5° of parallel → line-to-line distance; otherwise an angle, as before.
6. **The flip check also guards the inspector's value field** (it shares DIM-1's helper), with the same sentence as `refusal`.
7. **DIM-3's `checkValueCommit` runs after the placing click only when a value was typed**; its message then shows as the editor's `refusal` (the box is already closed).
8. **"NX"** counts the dimensioned circle's (or arc's) Equal set of the same kind (circles with circles, arcs with arcs), shown when it is 2 or more, on every radius or diameter dimension in that set.
9. **Interface additions** `DimensionEditing.valueBoxClosed(_:by:)` with `DimensionValueBoxEnding`, `ViewportTool.dragBegan(onDimension:at:modifiers:projector:)`, `SketchEditorEvents.openValueBox` are already in the overview's shared interfaces (folded in 2026-10-27); Tasks 6 and 7 implement them.

```swift
public enum DimensionKind {   // added cases
    /// Between the centres of two circles or arcs, or a circle or arc and a point.
    case centreDistance(SketchEntityID, SketchEntityID)
    /// Two lines: the distance from the second line's midpoint to the first line, along the first line's normal.
    case lineDistance(SketchEntityID, SketchEntityID)
    /// |Δx| between two points or circle/arc centres (either operand may be either).
    case horizontalDistance(SketchEntityID, SketchEntityID)
    /// |Δy| likewise.
    case verticalDistance(SketchEntityID, SketchEntityID)
}
enum Equation {   // added (internal)
    enum Axis: Hashable, Sendable { case x, y }
    /// side · (b − a)[axis] − d.
    case axisDistance(PointOperand, PointOperand, axis: Axis, Double, side: Double)
    /// side · (signedDistance(second.start, first) + signedDistance(second.end, first)) / 2 − d.
    case lineToLineDistance(LineOperand, LineOperand, Double, side: Double)
}
extension TermBuilder {
    func centre(_ id: SketchEntityID, ref: SketchConstraintRef?, needs: String) throws(SolveFailure) -> PointOperand  // a point, or a circle's/arc's centre
}
```

  `.centreDistance` builds the existing `.distance(centre(a), centre(b), value)` (its Jacobian is already tested); it refuses two
  points ("needs two circles or arcs, or a circle or arc and a point"). `.horizontalDistance`/`.verticalDistance` build
  `.axisDistance` (needs "two points, circles or arcs"), side = the sign of `(b − a)[axis]` at the warm start, +1 when it is 0
  (`|…| ≤ 1e-12`). `.lineDistance` builds `.lineToLineDistance` (needs "two lines"), side from the warm start as `side(_:_:)` does,
  the rows the mean of the two existing `Equation.signedDistance` rows. Validation is the existing length rule (> 0 mm).

### Task 4: Flip detection

**Files:**
- Create: `Sources/CreatorSketch/Solver/SketchFlipCheck.swift`
- Test: `Tests/CreatorSketchTests/SketchFlipCheckTests.swift`

**Interfaces:**

```swift
public enum SketchFlipCheck {
    /// The sine below which a corner or an arc has no side (1°).
    public static let straightLimit: Double          // sin(1°)
    /// True when a usable solve `after` turns a corner or an arc of `sketch` the other way from `before` (spec §7).
    public static func isFlipped(_ before: SketchSolution, _ after: SketchSolution, in sketch: Sketch) -> Bool
}
```

  Corners: every pair of line entities (normal or construction, in `entityIDs` order) sharing an endpoint entity; the turn is
  `cross(û₁, û₂)`, `û` the unit vector from the shared point to each line's other end. Arcs: `cross(start − c, end − c)` over the
  two lengths. Each is read from `before.points` and `after.points`; it is skipped when either reading is missing, a length is under
  1e-9, or `|sine| < straightLimit` in either; a flip is any pair not skipped whose two signs differ. An `after` whose status is not
  `isUsable` is never "flipped" (the caller refuses it for its own reason).

```swift
struct PendingDimension: Hashable, Sendable {
    enum Phase: Hashable, Sendable { case picked, entering, placing }   // picked: a circle's or arc's diameter/radius before the second click
    var aligned: DimensionKind          // the kind as picked (length, distance, centre distance, …)
    var kind: DimensionKind             // what it is now (aligned, or a horizontal/vertical one)
    var value: Double                   // mm or degrees
    var isDriving: Bool
    var labelPoint: Vector2
    var phase: Phase
    var isOrientationLocked: Bool       // a typed value (Decision 3)
}

}

```

  Flow: the completing pick measures with `Sketch.measuredDimension` (nil → `refusal = "That can't be measured."`, or for a length
  under 1e-9 "Those are in the same place: there is nothing to dimension."), sets `pending` (phase `.entering`, label = the click,
  orientation chosen from it), then calls `events.openValueBox(pendingID)` when driving, or goes straight to `.placing` when a
  reference. `valueBoxContent(pendingID)` = `units.editText(value)`. `commitValue(text, pendingID)` runs DIM-1's shared checks; an
  unchanged value is `.accepted` → placing, unlocked; otherwise the sketch with the pending dimension driving is solved: not usable →
  refused as DIM-1 words it; `SketchFlipCheck.isFlipped(solution, solved, in:)` → `.refused("This value would flip the sketch.")`;
  else `pendingOrigin` keeps the old sketch and solution, the editor shows the solved one (no `events.committed`), placing, locked.
  `valueBoxClosed(pendingID, .unchanged)` → placing; `.cancelled` → dropped. While placing, `hover` moves `labelPoint` (and, unlocked,
  re-chooses the orientation, the value being that kind's measurement and `isDriving` re-decided by `measuredDimension`); `click`
  commits the dimension (kind, value, `isDriving`, `labelPoint`) with `commit(_, "Dimension dN", named: SketchStepName.addDimension)`
  and, when locked, `Task { if let m = await events.checkValueCommit() { refusal = m } }`. Dropping restores `pendingOrigin`.
