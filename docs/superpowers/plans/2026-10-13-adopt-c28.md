## Findings that shape the plan (read first)

- **C28 documents ⌘Z after a selection write.** MetalUI `docs/testing.md` "Undo after a selection write" (`SL-O`, pinned in MetalUI by `theUndoContractAfterASelectionWrite`): a written selection ends the open typing group; ⌘Z removes only the text typed after it and restores the written selection. CT-d's second half is **answered**, so C25-7 is pinned with a test (Task 1) instead of "record, don't judge".
- **Driver verbs** (`TestWindow`, `MetalUITesting`): `setMarkedText(_:selectedRange:)`, `commitMarkedText()` (AppKit `unmarkText`: the marked text becomes committed), `commitMarkedText(_:)` (`insertText`: a candidate replaces the marked text), **`cancelMarkedText()`** (SDL's empty `TEXT_EDITING`: drops the composition, commits nothing), read-backs `markedText` and `markedSelection`. All `@discardableResult` returning `Bool`; `false` and nothing sent when no text field has the caret. Each runs one frame.
- **Behaviour measured through `AppWindow`:** marked text is not in `commentEdit.draft` or `pendingEntry`; `focusedElement.value` is the committed text (MetalUI divergence 325); the model's `selectedOffsets` is unchanged by composing; a commit publishes the caret after the candidate; a primary press on inert chrome or the viewport (C24's `AppWindowRoot` region) clears the focus, MetalUI drops the composition (`IM-I`), and `onChange(of: isFocused)` commits the draft as it stood before the composition (nothing of the marked text).
- **A selection write held back while composing (divergence 326, `SL-H`)** cannot be exercised from MetalCreator: the editor writes `CommentEdit.selection` only in `beginEditing`, never mid-edit, so no MetalCreator path writes the binding while a composition is open. The cover is "the opening selection survives a composition" (Review Focus 2).
- **CLAUDE.md** mentions neither the missing driver nor CT-d: unchanged.
- **Mid-line caret** is made with ⌥← (`typeKey(.leftArrow, modifierFlags: .option)`), not a click, because a click's offset depends on glyph metrics.

/// C25-3): marked text is in the field and not in the model's draft; committing it is one write and one undo step;
/// cancelling it changes nothing; the selection the editor opened with survives it; and a press elsewhere, which now
/// resigns the focus (C24), drops the composition uncommitted (MetalUI `IM-I`) and ends the edit with the text the
/// field held before it.
@MainActor
struct CanvasTypingCompositionWindowTests {
    let fixture = TypingFixture()

    func titleEditor() async throws -> AppWindow {
        let app = try await AppWindow.open(fixture.graph)
        app.window.doubleClick(at: app.titleBarCentre(ofFrame: fixture.box.id))
        #expect(app.editor.commentEdit?.kind == .frameTitle)
        return app
    }

    func noteEditor() async throws -> AppWindow {
        let app = try await AppWindow.open(fixture.graph)
        app.window.doubleClick(at: app.centre(ofComment: fixture.note.id))
        #expect(app.editor.commentEdit?.kind == .noteText)
        return app
    }

    @Test func markedTextInATitleIsNotInTheDraftAndTheOpeningSelectionStays() async throws {
        let app = try await titleEditor()
        #expect(app.window.setMarkedText("ni"))
        #expect(app.window.markedText == "ni")
        #expect(app.editor.commentEdit?.draft == "Bracket", "the model has not heard of the marked text")
        #expect(app.editor.commentEdit?.selectedOffsets == 0..<7, "and the selection the edit opened with is still the model's")
        #expect(try app.window.focusedElement?.value == "Bracket", "accessibility reports committed text only (MetalUI divergence 325)")

        app.window.setMarkedText("ni")
        app.window.setMarkedText("nihao")

        #expect(app.window.markedText == "")
        #expect(app.editor.commentEdit?.draft == "你好", "the candidate replaced the selected title")
        #expect(app.editor.commentEdit?.selectedOffsets == 2..<2, "the commit published the caret after it")

        #expect(app.editor.commentEdit?.draft == "你好!", "typing after the composition appends: the title is not selected again")

        #expect(app.editor.graph.frames[fixture.box.id]?.title == "Bracket")
        #expect(!app.editor.document.canUndo, "one step for the composition and the typing after it")

        #expect(app.window.markedText == "")

        #expect(app.window.markedText == "")

        #expect(app.window.markedText == "", "the composition was dropped, not committed (MetalUI IM-I)")

        let app = try await noteEditor()

        #expect(app.editor.commentEdit?.draft == "Line one")
        #expect(app.editor.commentEdit?.selectedOffsets == 8..<8, "the caret the edit opened with")

        #expect(app.editor.commentEdit?.draft == "Line one你")

        app.editor.document.undo()
        #expect(app.editor.graph.stickies[fixture.note.id]?.text == "Line one" && !app.editor.document.canUndo)
    }

    @Test func aCandidateCommittedMidLineLandsAtTheCaretAndPublishesTheCaretAfterIt() async throws {
        let app = try await noteEditor()

    @Test func aCancelledCompositionInANoteLeavesItsTextAndCaret() async throws {

        app.window.cancelMarkedText()

import CreatorGeometry
import CreatorGraph
import CreatorNodes
import MetalUI

@testable import CreatorApp

/// An input method composing in an inspector number field, through the app's real window (MetalUI C28, gap CT-d): the
/// marked text is the field's own, the model hears of the committed text only, and a press elsewhere while composing
/// drops the composition (MetalUI `IM-I`) and leaves no pending value (nothing was typed before the composition in the press test, so what is committed from before it is pinned by the canvas note and title tests, not here).
@MainActor
struct InspectorFieldCompositionWindowTests {
    /// The window showing a Rectangle node, selected, and its Width field clicked, all of it selected.
    func widthField() async throws -> (app: AppWindow, node: Node) {
        var builder = GraphBuilder()
        let node = builder.add(RectangleNode.self, at: Vector2(40, 40))
        let app = try await AppWindow.open(builder.graph)
        app.window.click(at: app.point(inCanvas: Vector2(60, 80)))
        #expect(app.editor.selection == [node.id])
        let fields = try app.window.elements { $0.role == .textField && $0.frame.origin.x.value >= Float(app.inspectorColumnStart) }
        let width = try #require(fields.first)
        try app.window.click(width)
        app.window.typeKey("a", modifierFlags: .primary)
        return (app, node)
    }

    @Test func markedTextIsNotAPendingValueAndACommittedCandidateIs() async throws {
        let (app, node) = try await widthField()
        #expect(app.window.setMarkedText("3"))
        #expect(app.editor.pendingEntry == nil, "the field holds the marked text; the model has no pending value")
        #expect(app.window.commitMarkedText("33"))
        #expect(app.editor.pendingEntry?.text == "33")
        app.window.typeKey(.return)
        #expect(app.editor.graph.nodes[node.id]?.inputValues["width"] == .number(33))
        #expect(app.editor.document.undoName == "Change Width")
        app.editor.document.undo()
        #expect(app.editor.graph.nodes[node.id]?.inputValues["width"] == nil && !app.editor.document.canUndo, "one step")
    }

    @Test func aCancelledCompositionLeavesTheFieldAlone() async throws {
        let (app, node) = try await widthField()
        app.window.setMarkedText("9")
        app.window.cancelMarkedText()
        #expect(app.editor.pendingEntry == nil)
        app.window.typeText("7")
        #expect(app.editor.pendingEntry?.text == "7", "the select-all survived: typing replaced the value")
        app.window.typeKey(.return)
        #expect(app.editor.graph.nodes[node.id]?.inputValues["width"] == .number(7))
    }

    @Test(arguments: InertSpot.allCases)
    func aPressOnChromeWhileComposingCommitsNothingOfIt(spot: InertSpot) async throws {
        let (app, node) = try await widthField()
        app.window.setMarkedText("9")
        app.window.click(at: try spot.point(in: app))
        try await app.window.runUntilIdle()
        #expect(app.window.markedText == "")
        #expect(try app.window.focusedElement == nil)
        #expect(app.editor.pendingEntry == nil, "no stale pending entry survives the press")
        #expect(app.editor.graph.nodes[node.id]?.inputValues["width"] == nil)
        #expect(!app.editor.document.canUndo)
    }
}

## User decisions

1. **A press on chrome while composing discards the composition.** MetalUI's `IM-I` (focus loss drops uncommitted marked text) plus C24 (a primary press on inert chrome or the viewport resigns the focus) means clicking the graph panel or viewport mid-composition loses the marked text, while text typed before it is committed. Options: (a) accept MetalUI's rule (note: `IM-I` is hygiene, not a platform measurement: record §102 says it was "measured red on arrival" for stale marked text returning on refocus, and `migration.md` says nothing relied on it; it was not compared with native behaviour, where AppKit text fields normally commit marked text when focus leaves); (b) ask MetalUI for commit-on-resign (marked text becomes committed when the field loses focus). **Recommended: (a).** The three canvas tests and one inspector test pin the current rule and flip easily if MetalUI changes; C25-3 states that `IM-I` is not a platform measurement and asks explicitly whether losing the marked text feels wrong on a real input source; if it does, (b) is requested from MetalUI and the four press tests flip.
