# NURBS surfaces (NS-1 to NS-5: nodes, kernel calls, shim)

Notes for this module, moved from the root `CLAUDE.md` (which Claude Code loads in every session) so they load only when work touches this folder. The project-wide rules, commands and toolchain notes stay in the root file.

NURBS surfaces, NS-1 (curves, sheets and Import Model: spec `docs/superpowers/specs/2026-11-17-nurbs-surfaces-design.md`, plan `docs/superpowers/plans/2026-11-17-ns-1-curves-sheets-import.md`; the `curve` socket type and `Value`/`Scalar.curve`, a `Curve` of `CurvePiece`s (lines, arcs, `BSplineCurve3D`), and a sheet, a `Solid` with faces and no closed volume; the `Surfaces` library category (`NodeCategory.surface`, sections Curves and Make; 98 built-in nodes after NS-1, 100 after NS-2, 104 after NS-3) holds Curve through Points (degree 3 or 5; degree 5 needs six points and refuses `closed` and end tangents, and is a true quintic interpolation since NS-3: before it the degree-5 option wrongly built a cubic for seven or more points), Curve from Edges, Profile to Curves, Planar Surface, Extrude Curve, Revolve Curve, Loft Surface and Sweep, and Import Model is in the Solid category; the Sketch node's open curves come out as `curves`. Extrude Curve, Revolve Curve, Loft Surface and Planar Surface give sheets only; **only Sweep can give a solid** (its "solid" option, with caps), and a Sweep with it off is a sheet. Sheets carry `BoundaryRole` on edges (start, end, rail, piece, imported; `TopoRole.boundary`); the shim's boundary-edge rule (`is_boundary_edge`) is: an edge with one distinct face that is not closed on that face (a seam is) and not degenerate (a pole or apex); it reports `faces == [f]`, so Edges by Tag and picks name a sheet's edges and survive a parameter change. Loft faces are `.side(loop: span, segment: k)` (a span per section gap when ruled, 0 when smooth) and sweep spans likewise, sweeps use RoundCorner transitions, and loft and sweep sections must have the same piece count. `Solid.isClosed` is edge-level and `Solid.hasOpenShell` face-level, and the latter is what refusals, facts and export use: **a face is on an open shell when its shell is not inside a `TopAbs_SOLID` (or is not closed)**, so closed bare shells (a closed curve revolved 360 degrees, a closed Loft Surface, a Sweep with "solid" off) are sheets while `isClosed` stays true for them, and a defective solid with a stray free edge (the bracket's union) is still a solid. The nodes that refuse a sheet in words are Boolean, Fillet, Chamfer, To Implicit, a signed Distance Field (unsigned works), the pattern shortcuts (their tools and part) and Pattern Feature; Section and Measure skip curves. Import Model reads STEP and IGES (`Kernel.readShapes`, linked or embedded, 256 MB; units from OCCT's factors, Unknown warns; a closed free shell that makes a valid solid becomes one (`solidify_closed_shell` in `cocct_import.cpp`, shared by `readShapes` and by `readModel`, which KiCad's component models use, so a vendor model stored as a bare closed shell stays a solid; a model that was already solids is returned untouched and keeps its face order), **a file's loose faces and free open shells form one sheet** (an unsewn compound, face indices file-wide; Sew (NS-5) joins them and Thicken and Offset Surface refuse them unsewn; so an IGES box is one sheet of six faces), free edges are chained into one curve per wire; **every solid and sheet of a file has its own names**: face and boundary-edge indices are offset by `body << 32` (body counts solids first, then sheets), as KiCad's component models are, so a pick on one body never matches another; `ImportedModelCache`, 512 MB; facts include "Picks: Last until the file changes."; `NodeSetting.modelFile`); File ▸ Import Model... inserts the node wired to an Output's `solid` and `curve` inputs in one step (a sheet-only file shows nothing in Final preview until its `sheets` output is wired). The viewport draws a sheet's back in the theme role `sheetBack` (after `shadeDark`; Dracula #6272A4, Alucard #635D97, Nord #5E81AC; face flag bit 8, `ShadeUniforms` stride 96, the ghost branch wins); zebra stripes and the field tint do not use `sheetBack` (a sheet's back is striped or tinted like its front); curves are items (`isCurve`, a cached display solid in `MeshSolids`, drawn in every mode in the reference colour, ghost curves faded, never picked). Export: STEP writes shells and wires, STL of an open mesh warns and leaves curves out, 3MF refuses a sheet before the save panel, and an Output holding only curves refuses STL and 3MF in its own sentence; the Output node has a `curve` socket; `SolidFacts` reads "sheet:" or "solid and sheet:" and the MCP solid entry has a `kind` key; the shim is `cocct_curve.cpp`, `cocct_sheet.cpp`/`.hpp` and `readShapes` in `cocct_import.cpp`; file format 14) code is done; its human checks (group NS-1) are pending.
NURBS surfaces, NS-2 (surfaces from curves: spec `docs/superpowers/specs/2026-11-17-nurbs-surfaces-design.md`, plan `docs/superpowers/plans/2026-11-18-ns-2-surfaces-from-curves.md`; 100 built-in nodes (104 after NS-3), the `.surface` category holding 10 (14 after NS-3); rulings R1 to R6 of the plan's header) code is done; its human checks (group NS-2) are pending. Network Surface (`NetworkSurfaceNode`, `Kernel.networkSurface(u:v:tolerance:tag:)`, `cocct_network.cpp`) makes a Gordon surface from u and v curves that cross: the order and direction of the curves are found, not given (R4: u curves sorted by where they cross the first v curve and the reverse, each turned to run like its first neighbour), skin and tensor interpolation degree is min(3, count - 1), the pole count is capped at 100,000 (refused with a sentence; the shim polls `occt_cancel`, so it is cancellable), and **it promises to lie within `tolerance` (default 0.01 mm) of every input curve, not exact interpolation** (a tighter refit failed on curved networks of five or more uneven curves); G0 only (R1: G1/G2 to a part along the borders is Match Surface's job in NS-4); naming R6: the face is `.side(loop: 0, segment: 0)`, the first and last u curves' edges `.boundary(.start)` and `.boundary(.end)`, the first and last v curves' `.boundary(.rail(0))` and `.boundary(.rail(1))`. Boundary Patch (`BoundaryPatchNode`, `Kernel.boundaryPatch(...)`, `PatchContinuity` G0 / G1 / G2, `cocct_patch.cpp`, `cocct_patch_g2.cpp`/`.hpp`, `cocct_patch_quad.hpp`) fills a loop of 1 to 16 pieces (a single closed circle is valid; a round hole is the commonest case), optionally through interior points and curves; one `continuity` for every bounding piece (R2), applied to the pieces that are a sheet's boundary edge (one face) and held G0 for curves and a solid's edges; **a G1 or G2 request with no piece on a sheet is held at G0 with "No bounding edge is a sheet's open edge, so the patch is only G0." whatever the number of sides**; G0 and G1 are `BRepFill_Filling`; G2 takes no interior points or curves (R3, refused "A G2 patch can't pass through interior points or curves.") and is the triangle machinery for three sides and a biquintic Coons patch (`cocct_patch_quad.hpp`) for four. The accepted G2 limits, documented and not bugs (G2 on general boundaries is a backlog item; every refusal sentence says to use G1): a bounding piece must fit a quintic within 1e-7 mm ("Piece N can't be followed exactly by a G2 patch; use G1 for this hole."), a four-sided G2 patch needs corners near 90 degrees and sides that run straight across their surfaces ("... Use G1 for this hole."), a round hole split into quarter arcs is refused for that reason, strong interior curves can pull a fill off a bounding piece (refused "misses piece N"), and a patch that would crease says "A G2 patch would crease here; use G1 for this hole." Naming R6: the face is `.startCap` and bounding piece k, in loop order from the first input piece, is `.boundary(.piece(loop: 0, segment: k))`; no new `BoundaryRole`. Sweep gained a second rail and a guide surface (`SweepGuide`, `orientation` 2 is a second rail and 3 a guide surface, both wired, never typed, and both refuse a profile that is a straight line: "A rail sweep needs profiles that aren't straight lines.", "A guide sweep needs profiles that aren't straight lines."; "Sweep takes one rail curve.") and `twist` (degrees, Frenet or Fixed only, R5: made with an auxiliary spine, the path offset by min(1 % of the path's diagonal, half the tightest radius of curvature) in a direction that turns by `twist x t` about the tangent; "Twist can't be combined with a rail or a guide surface." and "The path bends too tightly to twist along."); the inspector shows the twist control for Rail or Guide too while the node still holds a nonzero twist, so it can be cleared. The two-body continuity call is `Kernel.continuity(of:in:against:of:)` (the grade of a sheet's free edge against a face of another body). Network Surface's order is keyed to the first v curve's direction (u curves are sorted by where they cross it, so reversing or reordering that curve can swap the start and end names and move picks), refusals name curves by their place in the input ("U curve 2 and v curve 1 miss each other by 0.5 mm."), a curve that is closed is refused ("Network curves must be open; a closed curve can't be part of a network yet."), a rational piece (an arc) is approximated by a polynomial one within tolerance / 40 (degree 5, C2) before the build, and a grid over 100,000 crossings is refused before any curve is read. A nonzero sweep twist builds by parallel transport with an auxiliary spine, so on a non-planar path a twist of 0.01 degrees differs visibly from 0, and Fixed's binormal is not used once the twist is nonzero. A guide-surface sweep copies the path, gives its edges pcurves on the guide faces they lie on (within 1e-3 mm; each edge is held as an internal edge of a face over that surface, which is what OCCT's `BRepFill_EdgeOnSurfLaw` needs, else it silently takes the Frenet frame) and refuses a path that doesn't lie on the guide with "The path must lie on the guide surface."; a rail or guide wired while the orientation is Frenet or Fixed is ignored with the warning "The rail and guide are used only when the orientation is Rail or Guide." A Boundary Patch checks R2 first: with no bounding piece on a sheet a G1 or G2 request is held at G0 (with the warning) before G2's limits on interior points and sides are looked at.
NURBS surfaces, NS-3 (control points: spec `docs/superpowers/specs/2026-11-17-nurbs-surfaces-design.md`, plan `docs/superpowers/plans/2026-11-18-ns-3-control-points.md`; 104 built-in nodes, the `.surface` category holding 14; rulings R1 to R9 of the plan's header; file format 15) code is done; its human checks (group NS-3) are pending and its benchmark row `surface-3` is in `docs/verification/performance.md`. The shim is `cocct_control_net.cpp`/`.hpp` (nets, moves, `folds`, `surfaceInfo`) and `cocct_rebuild.cpp`. Rulings: R2 Rebuild keeps the face's trims (the new surface spans the old one's parameter range, so the pcurves and picks stay) and Rebuild Curve makes one B-spline piece of the whole curve with its ends pinned (clamped, or periodic when the source is periodic, needing degree + 1 spans); R3 the fit is ours, least squares over uniform knots (rows, then columns), not `GeomAPI_PointsToBSplineSurface`, so a span count is honoured; Rebuild Surface refuses a sheet of several faces ("Rebuild Surface takes a sheet with one face; this one has 2. Split it first.") and a closed solid ("Rebuild Surface takes a sheet; this is a closed solid."); a periodic source is rebuilt periodic (uniform periodic knots over the same range, a cyclic solve), so a rebuilt revolve is smooth and closed across its seam; the deviation grid is capped at 1,000,000 samples; R4 Edit Curve takes a curve of one piece ("Edit Curve takes a curve of one piece; this one has 3. Rebuild it first."; a line or arc is converted exactly); a curve's net is its exact trimmed segment, on read and on write, and a surface's net the whole underlying surface with its pcurves kept; only edges whose 3D curve no longer lies on the moved surface (9 samples, 1e-7) are rebuilt, so untouched lines and circles keep their kind. A folded surface is a valid OCCT shape and is never refused: Edit Surface warns "The moved surface folds over itself; zebra stripes, thickening and offsets will misbehave there." through `Kernel.folds`, but not while a drag is in progress (`readsScrubbing(for:)` is true only with moves, and `folds` is skipped under `context.isScrubbing`), so the warning appears when the drag ends; `occt_surface_folds` classifies no point on an untrimmed face, and the result of a move built while scrubbing (`Kernel.movingPoles(of:by:previewing:)`; Edit Surface passes `context.isScrubbing`) takes the pole hull as the bounds of a face on a B-spline surface of over 400 poles (`shape_bounds(…, pole_hull)`; `surface-3` is 9 ms a step), every other result having tight bounds. A slider drag anywhere re-runs an Edit Surface that has moves once (its cache key holds `isScrubbing`). A move or rebuild that would open an apex (a degenerated edge no longer one point) or a seam (the two pcurves of a closed non-periodic face no longer meeting; an edge's gap growing by more than `SurfaceNet.coincidence` = 1e-6 mm over its gap before, at nine samples) is refused "Moving these control points opens the surface at its apex; move the matching points together." ("… along its seam; …"; Rebuild: "Rebuilding opens the surface at its apex." / "… along its seam."), Rebuild Surface pins a collapsed boundary row to its point, and the mode selects every pole on one point (within 1e-6 mm, `SurfaceNet.coincidence`) together on a click, a box and a drag, so an apex moves as one; a periodic net draws its closing line. The mode (`CreatorApp/ControlNet`: `ControlNetSession` is the viewport's tool, `ControlNetKeys`, `ControlNetInspector`, `ControlNetBoxView`; `AppModel+ControlNet`, `AppModel.editControlPoints(of:)` from the inspector's "Edit Control Points" button or a double click, `endControlPoints()`): R5 X, Y, Z and N toggle an axis lock that holds for the next drags until pressed again, another lock is chosen or the mode ends (N is the surface normal at the dragged point's Greville parameters, and does nothing on Edit Curve); locks move by the closest point between the pointer ray and the axis line, falling back to vertical pointer motion (mm per point) within about 18 degrees of the view direction; R6 the mode works on one surface or curve at the top level (inside a group "Control points inside a group can't be edited yet. Edit them before grouping, or from the top level."; a list: "Edit Control Points works on one surface; this node gets 3.", "one curve" for a curve; the sentence goes when the wire does); R7 box select is a plain primary drag on empty space (replaces), a ⌘-drag toggles, Shift-drag stays the viewport's pan; R8 the net is drawn over the model (no depth test) and points are picked through it within 8 points on screen, the nearest to the camera on a tie; R9 starting the mode ends Measure, and while it runs sketching, picks, the model dimension tool and Measure are refused, MCP edits are refused ("MetalCreator is editing control points. Click Done, then try again."), and New, Open, removing the node or undoing it away end the mode (Edit Control Points during a pick cancels the pick and enters, as Edit sketch does). Esc during a drag cancels the drag, restoring the offsets from before it, and a cancelled drag leaves no undo step (`DocumentModel.discardCoalescedStep(key:)`); the mode stays; Esc with no drag leaves it; Esc belongs to the export sheet or an alert while one is up. Every drag is one undo step "Move Control Points" (typing one is "Change Control Point"), the drag sets `DocumentModel.isScrubbing`, and the Edit node's source is kept in `extraDemand` while its net is shown, given back when the mode ends or the node is deselected. A selected Edit Surface or Edit Curve node shows its net read only (`controlNetPreview`). Limits, accepted: the fold check samples per knot span and compares neighbours only within a span, never across an interior knot, and only warns, so a fold lying exactly on a knot line can be missed (NS-5 R10: a neighbour pair whose normals oppose is confirmed by refining the segment between the two samples into 64 steps, a fold's normal passing through zero and never resolving, so a needle-like spike no longer reads as a fold); a curve's net is its trimmed segment and a surface's the whole underlying surface (a trimmed face shows poles outside its trim); Rebuild uses uniform knots, so a curvature jump needs many spans; a closed source rebuilds periodic and needs degree + 1 spans ("A closed surface needs at least N spans…", a face covering only part of a periodic surface's period is rebuilt clamped over the face's range since NS-4, so it no longer gets that refusal).
NURBS surfaces, NS-4 (editing surfaces: spec `docs/superpowers/specs/2026-11-17-nurbs-surfaces-design.md`, plan `docs/superpowers/plans/2026-11-18-ns-4-editing-surfaces.md`; 110 built-in nodes, the `.surface` category holding 20; rulings R1 to R17 of the plan's header; file format 16) code is done; its human checks (group NS-4) are pending; the spec names no benchmark rows for NS-4. Kernel calls (each refused by default and in `FakeKernel` with a gerund phrase for `KernelError.unsupported`): `split(_:by:tag:)` giving a `SheetSplit` (cutter: `TrimCutter`, curves projected along a direction or normals, or a body), `subSheet(_:of:)`, `intersectionCurves(_:_:tag:)`, `extended(_:edges:length:mode:)` (`ExtendMode` Natural / Linear), `matched(_:edge:to:of:continuity:)` and `blendSurface(_:_:tag:)` (`SurfaceBlendEnd`; `PatchContinuity` G0 / G1 / G2). R2 pieces and cut edges are named by cutter element (`CutterName`: `.curve(index:piece:)` or `.face(tags)`) and side: a piece's faces keep their source tags plus `TopoTag(node, .cutSide(element, side))` per bordering element (`CutSide` inside / outside for a closed flat curve or closed solid, else front / back), and a cut edge carries `.boundary(.cut(element))`, so a pick on the disk cut by a circle still names the disk when the radius changes. Costs, documented: reversing an open cutter curve swaps front and back; reordering the cutter curves or inserting or removing one before another shifts `.curve(index:)`, so the keep picks of the pieces it borders no longer match: they are narrowed by origin and keep the nearest piece with "A picked region no longer matches exactly, …" (`TrimRegions.narrowedPick`; a pick whose source faces are gone too is still kept with that warning through the Trim's own `cutSide` group, and vanishes, "A picked region no longer exists", only when no origin group survives the normal filter, e.g. the sheet now faces the other way; all picks vanishing is "None of the picked regions exist any more…"), never a silent swap; pieces bordered by the same elements on the same sides share a name (a circle crossing a strip leaves two `.outside` pieces). R17 (with the final-review fixes): a Trim's own `cutSide` tags name the node itself, so paste and duplicate rename a copied node's picks to its copy (`EditorModel.insert` applies `Node.renamingTags`), every cut edge a Trim makes carries a `.boundary(.cut)` tag (an unmatched one the placeholder `.curve(index: -1, piece: 0)`; rare, it needs a failed ancestor lookup, and all such edges share that one name, so an Edges by Tag pick on one matches them all), and `TrimRegions.pieces(of:cutBy:)` counts only the cut edges of its own node so a Trim of a Trim's output partitions as the kernel does. A Trim keep pick is a `RegionPick` (`FacePick` plus `sharedBy`, `ConstantValue.regionPicks`, `NodeSetting.keepRegions`); `TrimRegions.resolve` warns "A picked region now names N pieces; …" only when a pick names more pieces than its `sharedBy` and otherwise keeps the piece nearest the recorded centroid silently, so between pieces that share a name the choice is geometric and a cutter change can swap them without a warning; the unit of keep is a piece (R4: a connected set of faces, never a lone face; Inside and Outside are even-odd over the closed flat curves or the closed solid and are refused for another cutter; Picked with no picks keeps everything and warns). R6: Split's list is ordered by the canonical sort key of each piece's smallest face tag set, ties by centroid (`SheetPieces.ordered`). R7: along a direction the cutter is the curves' prism, its extent taken from the union of the curves' and the sheet's bounds, along normals `BRepOffsetAPI_NormalProjection`; both are cut with `BRepAlgoAPI_Splitter`; a cutter part that doesn't divide a face is dropped with a warning and no division at all is a refusal. R8 (with its Task 7 erratum) Extend takes a sheet of one untrimmed face and edges that are iso-boundaries: Natural is `GeomLib::ExtendSurfByLength` (continuity 2, G2 across the old edge) and Linear appends one span in homogeneous coordinates (G1, exact for rational surfaces, refused where the weights fall below 1e-3 of the last), both calibrated to `length` and graded after the build; tags and adjacency are the input's. R9 (with its erratum) Match moves rows 0..c of one untrimmed iso edge to one target edge by fixed-weight least squares (so rational sheets match exactly), the along degree raised to at least 3, refinement doubling spans up to 5 times, ends more than 0.01 mm apart refused, a periodic edge refused until NS-G Task 3 ("Match Surface can't match an edge of a surface that closes on itself yet."; now R5 below), and the grade measured after the build. R10 (with its erratum) Blend builds a new sheet from quintic sections skinned like the G2 fillet's, G2 ends taking the face's normal curvature, a closed edge refused ("Blend Surface can't blend a closed edge yet."), naming as Network Surface's; Blend refuses G0 (R12). R11: Match and Blend asked for G2 build at G1 while `context.isScrubbing` with no warnings (`readsScrubbing(for:)` true for G2 only); Match's fold check always runs at G0 and G1 and is skipped only for the scrubbing G1 stand-in. R13: the two-body continuity grade needs most of its 32 samples (0 to 15 usable keeps "The edge doesn't run along that face.", 16 to 23 throws "Too few points along the edge lie on the other face to grade it.", 24 or more grades; Boundary Patch grades with it). R15: `AppModel.beginPick(for:socket:)` and the actions `pickTargetEdgesInView` (Match, socket "target") and `pickOtherEdgesInView` (Blend, socket "other edges") wire an Edges by Tag rule as Fillet's button does; "Pick regions in view…" and "Clear regions" are named undo steps "Pick Trim Regions" and "Clear Trim Regions", and a failed Trim forwards its own reason (`NodeFailure.recovery`) so the pick can be redone. R16 (the NS-3 follow-up): one `SurfaceNet.coincidence` = 1e-6 mm (and `cocct::kNetCoincidence`) for pole grouping (transitive closure, bucketed), the rebuild pin and the apex and seam guard; typing applies to a selection that is one coincident group; a drag on a partly selected group selects the whole group. File format 16 added `ConstantValue.regionPicks`, `TopoRole.cutSide` and `BoundaryRole.cut` in saved picks. Parked: Extend on multi-face or trimmed sheets, Match on trimmed edges, Blend on closed edges, chains of edges for Match and Blend, unique names for pieces that share a tag set (R17), and the older NS-2 and NS-3 items in the `nurbs-backlog-after-ns2` memory.

R5: **`EdgeInfo.tags` on a two-face edge made by sewing holds the union of the tags of the boundary edges sewn into it, and `Topology.edge(_:matches:)` also matches such an edge to a key whose one side is a subset of one of its faces' tags and whose other side is a subset of its own tags; every reader must test `isBoundary`, never `tags.isEmpty`**; `Topology.key(of:)` is unchanged and only Sew and Cap write edge records. R7 and R8: Thicken is the offset shell plus a ruled wall per paired boundary edge, sewn and solidified (a closed bare shell gives a solid with a void); a build that fails, has a tolerance over 0.01 mm or breaks `d x kappa < 1` searches a 0.01 mm grid by bisection (at most 20 builds) and refuses naming the largest distance that works. R9: a folded sheet is refused before any build; R10: the fold check is confirmed by refinement (above, the NS-3 paragraph).
