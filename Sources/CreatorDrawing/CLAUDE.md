# CreatorDrawing (drawings DR-1 to DR-5)

Notes for this module, moved from the root `CLAUDE.md` (which Claude Code loads in every session) so they load only when work touches this folder. The project-wide rules, commands and toolchain notes stay in the root file.

Drawings, DR-1 (sheets, views and PDF: spec `docs/superpowers/specs/2026-11-24-drawings-design.md`, plan `docs/superpowers/plans/2026-11-24-dr-1-sheets-views-pdf.md`, rulings R1 to R28 of the plan's header; file format 17) code is done; its human checks (group DR-1) are pending and its benchmark rows `drawing-1` and `drawing-2-warm` are in `docs/verification/performance.md`. Drawing mode (`AppModel.mode`, the top bar's segmented Model | Drawing, View ▸ Drawing on ⌘⇧D, which `GraphKeyBindings` no longer takes as Duplicate): sheets with an ISO 5457 / ASME border, zones and an ISO 7200 / Y14.1 title block, base and projected views of Output nodes by exact hidden-line removal in ISO 128 lines, saved, and exported as PDF and DXF. Two portable modules: `CreatorDrawing` (the saved `DrawingDocument`, `DrawingStyle` per standard, sheet geometry, Helvetica metrics, `ProjectionCache` and `DrawingProjector`, `SheetComposer` giving a `SheetPicture` of strokes and texts in sheet millimetres, `PDFWriter`, `DXFWriter`) and `CreatorDrawingEditor` (graph-free `DrawingEditorModel` and its MetalUI views; every edit is a `DrawingCommit`, the whole drawing document). The screen, the PDF and the DXF all draw the one `SheetPicture`, so they cannot disagree. The kernel call is `Kernel.projection(of:curves:frame:options:)` giving a `Projection2D` (visible and hidden sharp, smooth, outline, sheet-boundary and curve lines, each with its source edge or face), refused by default and in `FakeKernel` ("projecting views"); the OCCT shim is `cocct_projection.cpp` over `HLRBRep_Algo` and `HLRBRep_Data`, and TKHLR is linked on macOS, Linux and Windows (`CIPinTests` pins `Package.swift`'s toolkit list against the Linux Dockerfile's). R10 took the primary path (the shim reads `HLRBRep_Data` per edge and matches shapes by `IsSame`; no `HLRBRep_HLRToShape` fallback); two errata: `FaceIntL` holds silhouette lines and is an outline sourced to its face (only `FaceIsoL` is dropped), and a seam lying on a silhouette is kept as that outline. File format 17: the top-level graph's optional `drawings` key (`Graph.drawings`, one command `GraphCommand.setDrawings`, no evaluation, refused inside a definition; sheets in tab order, views sorted by `ViewID`), and `ViewState.drawing` (`isOn`, `sheet`; an optional key, no bump). Undo names are `DrawingStepName` through `UndoName.drawing(_:)`. Theme roles `drawingPaper`, `drawingInk` and `drawingHighlight` (group `ThemeRoleGroup.drawing`, last in `ThemeRole.all`; the same in every built-in theme). R11 line classes on paper; R12 screen strokes (`max(weight x zoom, 1 pt)`, dashes in sheet mm times zoom, `SheetSegment.cubics()` shared with the PDF); R13 lettering (cap height h, Helvetica's AFM advances, WinAnsi, a character outside it is "?" everywhere with one export warning per distinct original text; on screen one `Text` per glyph on the run's baseline); R14 sheets and zones; R15 title block fields; R16 mass from the Output's closed solids and a density; R17 the projection symbol at h = 2.5 mm; R18 view labels; R19 the cache (512 MB, LRU, keyed by the source solids' identities, a pending view stays drawn at 40 % opacity, and so does a view whose projection failed, with its sentence under it); R20 a view's source (removed, failed, mesh and empty Outputs, in words); R21 mode switching (entering ends the sketch, picks, Measure, the dimension tool and control points; an inspector action that needs the viewport switches to Model first); R22 the editor's scope (Select, Base View, Projected View); R23 PDF (PDF 1.7, a fixed object order, no dates, no `/ID`, numbers from integers by `PDFNumber`, so the bytes are identical on every platform); R24 DXF (R2000 with the OBJECTS AutoCAD needs, layers VISIBLE, HIDDEN, TANGENT, CENTER, DIMENSION, TEXT, HATCH and FRAME; the sheet, or one view at 1:1 in model coordinates); R25 export (`DrawingExportKind`, File ▸ Export PDF…, Export DXF of Sheet…, Export DXF of View at 1:1… and the top bar's Export menu; no progress card); R26 undo names per editor method; R27 performance (the canvas builds only views that meet the visible rect grown by 20 %, each `.equatable()`); R28 the window in Drawing (the field legend, mesh badge and the Section, Measure and Zebra panels are hidden, the slow-evaluation chip stays). Mass is in `DrawingSession+Facts` (a value holding a closed solid beside a sheet counts: `Solid.holdsClosedSolid`; the text rounds before it picks its unit); New and Open… commit typed inspector values first; `AppModel.settle()` also waits for the task that opens a sketch on a plane that had no result (`sketchOpenTask`); `WarmWorkPinTests.zoomElementRequestBound` rose to 250 for the segmented switch. Parked (the drawings backlog starts here): `HLRBRep_PolyAlgo` for very large parts, cancelling inside OCCT's hide, embedding a font subset, copy and paste of views (built in DR-5 R18 and R21), dragging tabs to reorder, tool shortcuts (built in DR-2), ANSI Y14.1's own zone counts and margins, hidden tangent lines, compressed PDF streams, DXF text in the reader's font widths, a progress sheet for drawing export; dimensions, sections, details, auxiliary views, GD&T, balloons, parts lists and MCP tools are DR-2 to DR-5.
Drawings, DR-2 (dimensions and notes: spec `docs/superpowers/specs/2026-11-24-drawings-design.md`, plan `docs/superpowers/plans/2026-11-25-dr-2-dimensions-notes.md`, rulings R1 to R27 of the plan's header; file format 18) code is done; its human checks (group DR-2) are pending and its benchmark rows `drawing-3` and `drawing-3-warm` are in `docs/verification/performance.md`. A sheet holds `annotations` (R2: `DrawingAnnotation` with an `AnnotationID`, an optional `view`, a kind of dimension, hole callout, centre mark, centre line or note, and `last: LastGood?`); deleting a view deletes its annotations, duplicating a sheet copies them. Anchors (R3, `AnchorTarget`: edge, corner, centre, outline, axis, point) are named by `EdgePick` and `FacePick` and accepted at pick time only when lasting (`AnchorNaming.isLasting`: no `.unnamed` role) and one run. `DrawingAnchorResolver` (R4) resolves by tag subsets, never `Topology.resolution` and never `EdgeKey.operandKeys`: one match or one run is held, several or none lost with a `LostReason` sentence; its `joinTolerance` (1e-4 mm) and `joinAngle` (0.01 rad) equal the kernel's internal run constants, held by the behaviour test `joinConstantsMatchTheKernels`; a chain, baseline or ordinate with one lost anchor is wholly lost. The measurer (`DrawingMeasure`, R5 and R6, decision 4) reads `EdgeInfo.curve` and `FaceInfo` projected by `ProjectionFrame.place`, never a projected polyline, and refuses a foreshortened number at the pick (a line not square to the view, a circle not seen face on, a cylinder not side on, an angle) and any dimension in an isometric view, which takes notes and leaders only. `DimensionInference` picks the kind (horizontal, vertical or aligned by where the placing click lies and by shift). The hole reader (`HoleReader`, R12) reads a plain, counterbored or countersunk hole, through or blind, from its mouth over `Topology` only, and words it with `DrawingSymbols` strokes. Numbers (`DimensionNumber`, R9) come from integers, never a platform formatter: millimetres drop trailing zeros, inches keep them and ASME drops the leading zero; the decimal sign is a document setting in ISO and a point in ASME; the minus is ASCII. Tolerances (R10: general, symmetric, deviation, limits, reference, basic and a fit) are `DimensionLabel` text; a fit is ISO 286 (`ISO286`, R11: sizes over 0 up to 500 mm, grades IT5 to IT11, tables checked against ISO 286-2; outside it is refused in words); the general tolerance is structured (`GeneralTolerance`: ISO 2768-1 class with an optional 2768-2 class, or an ASME table typed per row, shown in the title block, whose tolerance field is automatic now). The layout is `SheetDimensionLayout` in `CreatorDrawing`, beside the viewport's (R1: sheet millimetres, Helvetica's metrics, per-standard `AnnotationStyle` constants of R8: ISO text parallel above the line, ASME unidirectional in a break; text inside when it fits, arrows outside when short), so the screen, the PDF and the DXF draw one `SheetPicture`, which gained fills (arrowheads), rotated text, `.centre` strokes and `standard`, so the writers dash by the page's standard (R16). Centre marks are automatic on face-on full circles (`DrawingView.showsCentreMarks`, on by default, also for DR-1 files) and a Centre Mark or Centre Line tool adds more (R13); notes carry leaders (R14) and a sheet note whose leader lands on a view's line joins that view. Placement is relative to the measured geometry (R7), so a dimension keeps its distance as the part grows and moves with its view. Tools and keys (R17: Base View, Projected View, Dimension D, Baseline, Chain, Ordinate, Chamfer, Hole Callout H, Centre Mark M, Centre Line L, Note N; the letters act over the sheet canvas with nothing focused); selection, drag, nudge and Delete (R18); a cancelled drag leaves no step (`pointerCancelled` restores the base document and `events.discarded` becomes `DocumentModel.discardCoalescedStep(key:)`); fixed undo names (R19: "Add Dimension", "Move Dimension", "Change Tolerance", "Reattach Dimension" and the rest); the inspector's pages (R20). A lost annotation (R15, the anti-goal): it keeps its last good value with "?" (drawn warning-coloured on screen, in ink in files), the editor remembers the newest held `LastGood` (`DrawingEditorModel.remembered`, never an edit), the app writes it into `last` on save (`documentForSaving()`, `fileData(savingTo:drawings:)`, `didSave(to:drawings:)`: no undo step, the document not marked edited), lost ones are listed in the sheet inspector ("Lost references") and in every export's warnings one by one (ten per sheet, then a count), and a click on another line of its view re-attaches it ("Reattach Dimension"). R25: a pending view holds its annotations against the previous topology (`ViewContent.topology` travels with the projection) and a failed one loses them with its sentence, and R26: after every evaluation (any mode) `AnnotationRefresh.lastGood` refreshes `remembered` for every annotation of every sheet without projecting, off the main actor, a newer evaluation cancelling the older (notes are skipped). Group, Ungroup and Make Unique rename drawing anchors with the same table as picks (R21), so a dimension on a regrouped feature stays held. Export (R22): the PDF and the DXF of the sheet carry annotations (DXF layers DIMENSION and TEXT, CENTER linetype by standard); the new kind `dxfViewWithAnnotations` ("DXF of View at 1:1 with Annotations…") maps a view's annotations back to model millimetres. R23 format 18 (an older build refuses the file rather than dropping annotations). R24 composing resolves every annotation each time (`drawing-3`); caching resolutions is parked unless it passes 4 ms. R27 the editor's `replaceDocument` prunes selection and picks, `DrawingSheet.removeView` removes its annotations, and `ShoulderSide` and `SheetDimensionLayout.leader` fix the leaders' shoulders. Pulled in from the DR-1 backlog: dashes by the page's standard, `pointerCancelled`'s rollback, tool shortcuts and drawing anchors in Group. Parked: dual dimensioning, dimensions in isometric views, jogged ordinate leaders and automatic de-cluttering, fits over 500 mm or outside IT5 to IT11, hole counts and tolerances in callouts, dimensions of ellipse and B-spline edges, part-lost chains, in-canvas note editing, cached anchor resolution, narrowing a face anchor that matches nothing, freeing a joined note from its view, more than 10 lost annotations listed per export, refreshing notes' leader points outside a compose, and the DR-1 items not listed above.
Drawings, DR-3 (sections, details and auxiliary views: spec `docs/superpowers/specs/2026-11-24-drawings-design.md`, plan `docs/superpowers/plans/2026-11-26-dr-3-sections-details.md`, rulings R1 to R17 of the plan's header; file format 19) code is done; its human checks (group DR-3) are pending and its benchmark row `drawing-4` (a section of the bracket's Top view through the holes, cold: median 12.37 ms, budget 1 s) is in `docs/verification/performance.md`. R1: the cut is one kernel call composed in Swift, `Kernel.cutAway(_:by:tag:)` (a `SectionCutter`; `nil` when nothing is left; the default and `KernelUnavailable` throw `unsupported("cutting sections")`, `FakeKernel` too unless a test sets `setSectionCutHook(_:)`, which is async); `OCCTKernel` extrudes R2's removed polygon with its own `extrude` and subtracts it inside one `OCCTKernel.serialized`, checks the result (`isValid`, else "the section couldn't be cut through this part."), with two box-corner shortcuts before any boolean; no new C++. R2: `SectionCutter` (`CreatorKernel`: frame, points in the parent's model plane, unit `viewing`) alternates cut, step, cut, parallel and square within 1e-9; `validate()` gives every kernel the same refusals; points are positions, not anchors, and a line is moved whole ("Move Cutting Line"), never reshaped. R3: `SectionFrame` (`CreatorDrawing/Sections`) gives a section's frame, side (first angle: the view lies the way the arrows point; third angle the other) and alignment (a horizontal line aligns `.vertical`, a vertical one `.horizontal`, a slanted one is a free view drawn upright; the editor snaps the first segment within 5 degrees unless Shift is held); the stored orientation is always `.custom(SectionFrame.frame(for:))` and decoding repairs it. R4: the cut tool of solid i is `NodeTag(node: SectionCutter.toolNode, item: i)` (a fixed `NodeID`), a cut face is `.side(loop: 0, segment: k)`, a cut edge is named by the part face it bounds and the segment, so dimensions on cut edges are lasting, a line moved until a cut leaves the part loses them `.missing` (never another cut's edge); projected lines bordering a step face (odd k) are dropped (no line at a step, ISO 128-40); hatch is drawing only, never an anchor or pick. R5: `HatchRegion`, `HatchPattern` and `HatchBand.bands(for:)` (the regions of `Kernel.section` of the original solid by each cut's plane, each kept with its cut's band along the axis that holds the line's direction, open at the line's own ends whichever way it was drawn); sheets are never sectioned (a value of only sheets has its cut edge and no hatch, a mixed value hatches its closed solid only; a failed `Kernel.section` warns "The cut faces of a part couldn't be hatched."); lines are thin on `.hatch`, each part at its own exact direction (45, 135, 30, 120, 60, 150 degrees from constants with `(0.5).squareRoot()` and `(3.0).squareRoot() / 2`, never `sin` or `cos`, so the PDF's bytes match on every platform), spaced by `DrawingStyle.hatchSpacing(for:)` (2.5 mm, 4 mm on `SheetSize.isLarge`) on lines `n . x = j x spacing` so regions line up across a step. R6: `SectionMarks` and `SectionMarkStyle.of(standard)` draw the cutting line on the parent (a `.centre` stroke on `.center` with thick solid ends and corners in ISO, thick throughout in ASME), arrows on `.dimension`, the letters and a detail's circle; every mark has `view` = the parent and `mark` = the derived view; marks show only while the parent exists and its frame equals the stored one, else `DerivedViewNotices` says so in words; `DXFWriter` writes group 6 `Continuous` for a `.solid` stroke on CENTER or HIDDEN (which also fixes DR-2's small centre marks and changed the `a4Sheet` DXF digest). R7: `ViewLetters` gives a derived view its letter at creation (A to Z without I, O and Q, then AA, AB; never renumbered) and `ViewLabel` reads "SECTION A-A (1 : 1)", "DETAIL B (5 : 1)", "VIEW C (1 : 1)" (ASME without spaces in the scale). R8: `DetailCircle` in the parent's model plane; `DetailClip` clips the parent's content exactly (lines stay lines, arcs arcs, ellipses elliptic arcs), carries `ViewContent.hatchClips` so a detail of a detail or of a section clips its hatch at every ancestor circle, and `ViewContent.framing` is what a view centres on; no new hidden-line run; the default scale is the smallest preferred one at least twice the parent's, else 50 : 1. R9: an auxiliary view is picked on one straight edge square to a non-pictorial parent (`AuxiliaryRule`; a `.corner` candidate picks its edge, a `.centre` is refused), stores `AuxiliaryArrow` and is free, labelled "VIEW C"; the face shows true size. R10: `ViewKind` gained `section`, `detail`, `auxiliary` and `DrawingView.derivation` (`ViewDerivation`) is set exactly for them; **source carries to every descendant** and orientation to details; deleting a parent keeps its derived views with the notices; **no derivation cycles** (the editor never makes one, decoding breaks them, every walk keeps a visited set). R11: `DrawingSheet.isPictorial(_:)` (false for sections and auxiliary views; a detail reads its parent's) is what every dimension refusal reads, so an auxiliary view of an inclined face and a detail of it take dimensions at true length; `ProjectedViewRule.refusal(for:)` refuses a pictorial parent, a detail parent and a section or auxiliary view whose frame runs along no axis. R12: file format 19 (`ViewDerivation` is a keyed container with a `type` string; `derivation` and `letter` written only when present; decoding drops a derived view with a missing or wrong derivation, breaks cycles by dropping the lowest `ViewID` of each, repairs letters and a section's orientation). R13: tools Section, Detail and Auxiliary on S, E and U, Return finishes a cutting line (`DrawingKey.finish`), drafts (`sectionDraft`, `detailDraft`), a press on a mark selects its derived view and a drag moves the mark ("Move Cutting Line", "Move Detail Circle", "Change Detail Circle"), the inspector's derived pages. R14: `DrawingSession` keys a section's request by its cutter, cuts through `ProjectionCache.sectionCut(of:index:cutter:tolerance:kernel:)` (per solid identity, counted against the cache's limit), computes details on the main actor parents first, refreshes last good values per kind, and (pulled from the backlog) prunes `wanted`, `applied`, `flights`, generations and contents of views on no sheet and retains curves in `RequestKey`; curves on a section's Output are left out with a warning.
